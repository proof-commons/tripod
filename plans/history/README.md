# Backlog History

This directory holds this repository's own closed records, moved
verbatim out of maintained planning documents once the work they
describe finished. A completed gate record and the finding register of a
remediated review are evidence about the tree they were written for;
keeping them in the backlog made the backlog grow without making it more
useful, because none of it is live work any more.

Archived history is excluded from the load-bearing documentation weight budget and accounted against the separate archive budget instead, under the weight rule in [the plans README](../README.md). The exclusion is by role, not by provenance: like the drafts, guides, and reviews archives, nothing here is revised to keep pace with the living tree, so a weight warning could only ask an author to falsify a settled record. What a settled record is nonetheless kept current in, and what it never changes for, is stated with the archive rule below.

## Archive rule · `rule:history:authority`

A record here is history, never authority. It states what passed on a
named tree at a named time; it is not evidence that the current checkout
passes, and it never overrides the backlog, an ADR, a package contract,
or an accepted decision. Live work stays in [the backlog](../backlog.md),
which keeps a stub at each moved section pointing here.

A section moves here only once its batch is closed. Plan-local labels
move with their sections unchanged, so citations of them keep resolving;
the backlog stub that replaces a moved section carries no label.

A settled record is not revised to keep pace with the living tree: it states what passed on a named tree at a named time, and a record edited to agree with today's prose would stop being a record of anything. What a record preserves is its content — what was planned, what was measured, what was decided — and a name is not content. The repository's own name, its organisation's, and the names of its packages are identity: they belong to the thing the record is filed in rather than to the measurement the record carries, and a record that spells a name the project no longer uses sends a reader looking for something that does not exist. So an archive converges on the current name exactly as a living file does, and is otherwise unrevised. A record changes for a ruling that retires a passage it carries, and for nothing else.

The distinction is testable rather than rhetorical: converging a name changes no figure, no verdict, no date, no wall time, and no statement about what a tree contained, so an edit to an archive that alters one of those is not a name convergence. Where the two meet inside one token the rule still cuts between them. A hashed separator or a wire tag quoted in a record carries a name and a version component, and the version is a figure: the record says what it ran under, so the name converges and the version stands, even where the living tree has since stepped it for a migration the record predates.
