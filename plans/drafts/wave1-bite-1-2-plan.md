# Wave 1 bite-1.2 landing plan · `sec:w1b12:plan`

This is a proposal, not a disposition or authorization to change code. It reads `0.7.96-dev` under (`rule:phase7:wave1-home-rulings`) and plans (`task:guide15-exec:bite-1-2-deliverables`), (`setup:guide15-exec:bite-1-2-files-and-packages`) and (`gate:guide15-exec:bite-1-2-gate`). The stable declarations and home are settled (`rec:phase7:wave1-declarations`); compiled keyed plans are not. Proposed new paths and API names below are explicitly provisional. No build, test or measurement was run for this study.

**Disposition (Adopted sequence and decisions)** · `rec:w1b12:adoption`

The six-step sequence is adopted for bite 1.2. The four proposals below are adopted: (`q:w1b12:api`) uses `compiler::keyed_plan`, `plan(&BoundCompilerInput<KeyedOwner>, limits)`, immutable `KeyedPlan` and explicit revalidation, with exact typed error/projection inventory settled at step-3 review; (`q:w1b12:keys`) uses compiler-private structural namespace/domain/payload keys and reverse registries, without an interner or digest, with the step-1 inventory reviewed before step 3; (`q:w1b12:cost`) reports distributions and gate-budget impact without a numerical threshold or speedup claim, with the reviewed node runner, retained artifact location and incremental-edit recipe settled at step 5; (`q:w1b12:evidence`) publishes typed per-consumed-handle MERGE obligations and leaves concrete target evidence to bite 1.3. The frozen pre-refit baseline is `0.7.96-dev`; the measurement harness is deferred to step 5. These dispositions govern the proposals below; no measurement has been performed.

**Gate (Every landing)** · `gate:w1b12:landing`

Each code step runs node formatting, clippy with `-D warnings`, rustdoc and compiler package tests, including preservation and all retained controls, before landing. Include architecture/realization tests when their public types are consumed or their manifests change. Use the scoped code gate for affected packages, with the plans/lint registrations allowed explicitly; fast check alone runs no tests. The final gate covers architecture, realization, compiler, model, tapscript, linker, transaction and vectors, lint and plans. No native capture is needed. Register new files in Meson and document production spans/events under ADR-026. Numbers below are planning estimates including tests, docs and registrations, not measured edit footprints; overlapping file sets are not additive.

## Six ordered steps · `sec:w1b12:steps`

### 1. Strengthen the oracle and reserve the baseline · `step:w1b12:oracle`

**Scope: 6–10 files.** Update `packages/compiler/src/tests/engine_cases_tests.rs`, `engine_lifecycle_tests.rs`, test registration, Meson and test documentation; add a proposed `src/tests/engine_measurement.rs` harness only if required by the measurement protocol below. The current eligibility comparison checks lengths (`packages/compiler/src/tests/engine_cases_tests.rs:245`); compare complete canonical rows instead: keys, multiplicities, entries, options, carrier quantification, layout and empty causes, across every existing representation and SOURCE/MERGE/joint scope. Rename the record-mutant lifecycle test at `packages/compiler/src/tests/engine_lifecycle_tests.rs:78` to say it mutates records; retain the nine declaration-shell tests separately.

**Controls and handoff.** Add equal-length wrong-key, wrong-option, wrong-quantification/layout and wrong-empty-cause subjects beside accepted rows; prove that each comparison detects the changed coordinate. Reuse existing lowering, stage algorithms and preservation recipes unchanged. Inventory all identity-bearing positions and adapter types/variants/functions/conversion arms before changing them; retain the inventory with the later result record. Freeze the measurement protocol and baseline reference now, without replacing the preservation test. Pass (`gate:w1b12:landing`). This closes ruling 178 and hands stronger equivalence checks and an uncontaminated baseline to step 2; no performance claim is made.

### 2. Consolidate encoding and move bound owners · `step:w1b12:owners`

**Scope: 10–16 files.** Add proposed `packages/compiler/src/input/owner.rs` and `src/engine_identity.rs`; adapt `input.rs`, `engine_attestation.rs`, `engine_keyed.rs`, identity tests, `lib.rs`, Meson, README and TRACING. Move owner struct definitions and accessors while preserving `compiler::input::{AttestationOwner, KeyedOwner}` paths and sealed binding. Keep owner-specific lowering private in its present modules. One internal encoder consumes architecture's semantic namespace and encodes transaction sides; replace attestation's literal namespace/side helper (`packages/compiler/src/engine_attestation.rs:26`, `packages/compiler/src/engine_attestation.rs:375`) and keyed local spellings, without changing their bytes.

**Controls and handoff.** Pin every old side/namespace spelling, input/output distinction and cross-owner separation; retain external owner-type mismatch and public-item inventories in default/feature states. No engine record, lowering callback or public owner constructor may escape. Reuse declaration validation and analysis unchanged. Pass (`gate:w1b12:landing`). This closes rulings 174 and 176, handing one encoding owner and stable owner paths to the key refit. Compiler's feature stays until step 6.

### 3. Replace identity-only unions and measure the adapter reduction · `step:w1b12:keys`

**Scope: 22–35 files; split into two green commits if necessary, identities first and consumer adaptation second only where each compiles independently.** Inventory then adapt `engine_records.rs`, `engine_proof.rs`, `engine_foundation.rs`, `engine_placement.rs`, `engine_coverage_graph.rs`, their joins, `engine_attestation/*.rs`, `engine_keyed.rs` and affected tests. Existing examples are `OperationKey`/`RelationKey` (`packages/compiler/src/engine_records.rs:175`), while `CaseKey`, `CarrierKey`, `LayoutKey` still expose owner vocabulary (`packages/compiler/src/engine_placement.rs:15`). Follow expression, fact, requirement and coverage identities transitively; do not assume every enum is an identity. Keep semantic discharge, evidence, quantification and requirement variants explicit.

**Controls and handoff.** Use complete namespace-qualified structural keys with owner-held reverse registries, preserving injectivity, ordering and typed refusal restoration. Test same-local-code cross-owner separation, distinct payloads, permutation stability, missing reverse entries as typed refusals, and every retained stage join. No hash, ordinal allocation, callback or post-binding owner selection. Reuse all stage algorithms and the attestation compatibility publication; remove only conversions proven redundant. Publish the before/after adapter inventory by category, explaining required residual conversions; do not promise a numerical saving. Pass (`gate:w1b12:landing`). This discharges ruling 172 subject to review of the measured reduction; a larger or non-reducing adapter reopens that ruling rather than being silently accepted. An independent review here is valuable: key completeness and reverse mapping errors can hide behind green happy-path tests.

Independent review should focus on publication completeness and validator independence before calling these plans stable.

## Decisions to settle before dependent work · `sec:w1b12:decisions`

**Proposal (Public plan boundary)** · `q:w1b12:api`

Approve step 4's proposed `compiler::keyed_plan` with `plan(&BoundCompilerInput<KeyedOwner>, limits)`, an immutable `KeyedPlan` and an explicit revalidation entry, or select another spelling before implementation. Recommend this owner-typed facade over genericizing the attestation public projection: it adds no engine dispatch and preserves existing callers. Its projection must include scope/binding, per-relation assignments and quantification, coverage, evidence and search limits/reports, with no raw record payload. Settle the exact typed error/projection inventory during step 3 review before freezing the facade. The rulings require this boundary but do not prescribe its names.

**Proposal (Complete opaque keys)** · `q:w1b12:keys`

Recommend compiler-private structural namespace/domain/payload keys with deterministic full owner identity and retained reverse registries, using step 2's encoder. Approve the inventory and representation before step 3; neither an integer interner nor a digest is justified by the evidence. A field-by-field injectivity/order proof and collision controls decide any unresolved encoding choice. Ruling 172 requires an auditable reduction, not a preselected percentage; report actual adapter categories and reopen if the reduction is illusory.

**Proposal (Measurement question and thresholds)** · `q:w1b12:cost`

Recommend the first campaign answer “what are the per-subject and clean/incremental costs of the production candidate relative to the unchanged attestation baseline?”, without using noisy differences to change the accepted home. Approve the runner, retained artifact location and incremental-edit recipe before step 5; no node run is authorized by this draft. There is no governing numerical regression threshold. If a performance-based key/home comparison is desired, fix its practical wall/CPU/build thresholds and repetition policy before capture; otherwise report distributions and gate-budget impact, and make no speedup claim. Any correctness stop still takes precedence.

**Proposal (Plan obligations versus target evidence)** · `q:w1b12:evidence`

Recommend naming the two MERGE carriers as typed per-consumed-handle runtime obligations, with authenticated birth-position and same-key output-0 requirements left for bite 1.3; named carriers do not certify an emitted implementation. SOURCE recognition, reconstruction, acceptance and finality remain explicit evidence premises. Confirm this handoff in the public projection review: if a consumer needs concrete target capability admission now, define that additional scope before changing the engine. No separate decision is needed to defer the 1,565 refusal: ruling 180 already assigns it to bite 1.4.
