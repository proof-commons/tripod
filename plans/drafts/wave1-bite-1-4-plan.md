# Wave 1 bite-1.4 landing plan · `sec:w1b14:plan`

The initial study below proposed a sequence and decisions; (`rec:w1b14:adoption`) now governs them. It read `0.7.108-dev`, takes the explicit handoff from (`rec:w1b13:closed`) and (`rec:w1b13:members`), and implements (`sec:wave1:bite-1-4`), (`proposal:wave1:bite-1-4`), (`task:guide15-exec:bite-1-4-deliverables`) and (`setup:guide15-exec:bite-1-4-files-and-packages`). Rulings 162 and 163 at (`rule:phase7:wave1-realization-rulings`) and 180 at (`rule:phase7:wave1-home-rulings`) govern the construction envelope. No build, test or native execution was run for this study; the documentation gate checks this plan, not its implementation.

**Disposition (Adopted sequence and decisions)** · `rec:w1b14:adoption`

The six-step sequence is adopted for bite 1.4. The four recommendations below are adopted with their reasons and review boundaries; the original proposals remain as the record of the reasoning.

(`q:w1b14:curve`) is adopted: production curve arithmetic is a transaction-owned adapter over the existing workspace `secp256k1-zkp` safe wrapper, with transaction's existing tagged hash computing the Elements tweak. This adds no second curve or hash implementation, keeps the independent conformance arithmetic as the comparison oracle, and places curve provenance with the commitment owner. Step 2 records the dependency-role change from reference oracle to production in the transaction contract and root dependency documentation, including the exact safe API, features and exceptional cases. If the wrapper cannot implement the fixed recipe, step 2 stops and names the missing capability.

(`q:w1b14:inputs`) is adopted: public requests take parent transaction bytes, selected outpoints and checked spending capabilities; content addressing and canonical decoding are validated locally. The first packet supports only the existing decoder's envelope, with no issuance or peg-in anywhere in a parent. Unsupported serialization produces a typed unsupported-form result, not a covenant-invalid parent. Inclusion, unspentness, retrieval and finality remain external obligations, because local reproduction is not chain recognition and widening the shared decoder needs its own serialization review.

(`q:w1b14:envelope`) is adopted: typed structural construction is separate from admission against the measured policy envelope. Only the recorded envelope — one P2WPKH sponsor, successor/change/fee outputs, explicit policy asset and the sponsor-signature bound — earns the 1,564 maximum; a request outside it cannot present as admitted. Step 4 proposes the two exact entry and error shapes for review. Rulings 162 and 163 admit a measured envelope, not a general law.

(`q:w1b14:surface`) is adopted: linker owns `LinkedKeyedBundle`; transaction owns distinct SOURCE and MERGE request types with private checked fields, sealed authenticated input and commitment values, a separate ordinary funding-signature phase and immutable materialized output. No revalidating entry is added in this bite. Exact names, projections and errors are reviewed after steps 1 and 3, before step 4 depends on them. The zero-relocation reading is approved in step 1 only once its occurrence inventory is checkable. This keeps one authority boundary per artifact and preserves owner errors intact.

Independent review follows steps 1, 2, 3 and 4, and examines the gate packet at step 6; step 5 is reviewed with that packet. These checkpoints settle reference closure, commitment provenance, authenticated classification and construction admission before their downstream consumers rely on them.

## Decisions needed before implementation · `sec:w1b14:questions`

**Production curve admission** · `q:w1b14:curve`

Recommend a transaction-owned adapter over the existing workspace `secp256k1-zkp` safe wrapper, with transaction's existing tagged hash computing the Elements tweak and the wrapper performing lift/tweak/point arithmetic. `Cargo.toml:49` currently admits this dependency as a reference oracle for tests, and `packages/transaction/Cargo.toml` has no curve dependency: production use requires an explicit contract/dependency-role disposition before step 2. Do not move or copy the conformance BigInt implementation, add raw FFI, or claim independence from the node's underlying library. Keep the independent oracle as the comparison. Review the exact safe API, exceptional cases and dependency features in step 2; if it cannot implement the fixed recipe without a second implementation, stop with the unsupported capability identified.

**Authenticated input boundary** · `q:w1b14:inputs`

Recommend parent transaction bytes plus selected outpoints and checked spending capabilities as the public request input; validate content addressing and canonical decoding locally, while retaining inclusion, unspentness, retrieval and finality as external obligations. Do not trust a claimed txid/script/record count or treat local reproduction as chain recognition. The present decoder refuses issuance and peg-in anywhere in a parent (`packages/transaction/src/bytes.rs:710`), so the initial supported predecessor envelope must say so, including collateral flagged inputs in a parent; unsupported serialization is not a covenant-invalid parent. Recommend this explicit subset for the first packet rather than expanding the shared decoder. Any broader predecessor support needs a separately scoped serialization review. At the spending-input boundary refuse flagged members and preserve ordinary target-valid collateral through checked capabilities, not through a new ASH restriction.

**Open construction versus measured policy envelope** · `q:w1b14:envelope`

Recommend separating the typed structural construction result from policy admission. Structural construction preserves permitted target-valid extra inputs and outputs; the measured standard envelope additionally requires exactly the recorded one P2WPKH sponsor, successor/change/fee outputs, explicit policy asset and sponsor signature bound. Only that envelope earns the 1,564 maximum; a changed output count, sponsor type, asset/witness form or standard-weight policy must not inherit it. Such a request can retain a structural artifact with an explicit unadmitted-policy result, or be refused by the admitted-construction entry, but cannot masquerade as admitted. Step 4 should propose the exact two entry/error shapes for review. Policy readings and fee selection are explicit request data checked against computed bytes; final admission under ruling 162 still requires the admitted measurement-(e) observations repeated on final bytes, which bite 1.6 owns. This avoids choosing a new dust threshold or claiming the historic measurement is the final funding recipe.

**Stable request/linked surface** · `q:w1b14:surface`

Recommend linker-owned `LinkedKeyedBundle` and transaction-owned distinct SOURCE/MERGE request types with private checked fields, sealed authenticated input/commitment values, a separate ordinary funding-signature phase and immutable materialized output. No caller-authored covenant script, record total, creator secret or vectors descriptor enters the production authority boundary. Exact public names/projections/errors should be reviewed after steps 1 and 3, before step 4 depends on them; retain owner errors without collapsing their stage or identity. The current leaf has no unresolved literal: approve the zero-relocation reading in step 1 only after its occurrence inventory is checkable. No second planner or automatic candidate selection is proposed.

## Keyed commitment for review · `rec:w1b14:commitment`

Step 2 implements schema 1 from `packages/tapscript/src/keyed_constructor.rs` in transaction's `keyed_curve` and `keyed_taproot` modules, under (`rule:transaction:keyed-curve`) and (`rule:transaction:keyed-commitment`). `commit_keyed_bundle` consumes the sealed linked material without rewriting its 52-byte leaf, invoking a planner or reading linker constants as commitment policy. It recomputes the NUMS internal x from the public uncompressed generator, hashes the sole leaf with the existing transaction encoder/hash, treats that leaf as the complete root, computes the unreduced big-endian Elements tweak, obtains Q = P + tG and Q's parity, calls `witness_program_script` for witness v1, and builds the keyed depth-zero control. Existing ASH control assembly is untouched.

**Dependency role and exceptional cases.** The existing workspace `secp256k1-zkp` safe wrapper now also supplies production public arithmetic through a transaction-owned adapter, as adopted in (`q:w1b14:curve`). The wrapper is pinned to `=0.11.2`; this edge disables defaults and requests `std`, while `elements` adds features in a unified build as recorded below. No signing feature exists: the verification-only context and no secret input establish that API boundary. No direct raw-FFI dependency is added. The adapter calls `XOnlyPublicKey::from_slice`, `Scalar::from_be_bytes`, `Secp256k1::verification_only`, `XOnlyPublicKey::add_tweak`, `serialize` and `Parity::Odd`. Unliftable x maps to `InternalKeyNotAPoint`; t at or above n maps to `TweakAboveGroupOrder`, never modular reduction; zero is valid; the infinity sum maps to `TweakedPointIsIdentity`. After valid x/scalar parsing, the wrapper's subsequent conversion/parity error branches cannot occur for finite valid library output. The real scalar core tests G+0, G+(n−2)G = −G with odd parity, invalid x, t=n and G+(n−1)G; private capability injection tests the same constructor boundary without pretending to have found hash preimages. This C-library-backed production use agrees with the node's library family and is not independent evidence. The first-party conformance arithmetic remains the independent oracle and a dev-only consumer; transaction imports neither it nor vectors in production and reuses its existing tagged hash.

**Public inventory.** `keyed_curve` exports the public zero-sized `KeyedCurve` implementing the existing supplied capability, with no inherent constructor or signing API. `keyed_taproot` exports five types and three functions: immutable `KeyedCommitment`, sealed borrowed `AuthenticatedKeyedPredecessor`, non-exhaustive `KeyedCommitmentRefusal` (six variants), non-exhaustive `KeyedAuthenticationRefusal` (five variants), non-exhaustive `KeyedSpendPath` (two variants), `commit_keyed_bundle`, `authenticate_keyed_predecessor`, and `authenticate_keyed_path`. ## Serialized input census and requests · `rec:w1b14:inputs`

**Disposition of capability checking.** Request-time checking establishes canonical parent/output and capability-offer binding, not spending authority. A collateral row retains the selected output's asset, value and script from its decoded parent; an optional existing `SponsorCapability` must name that exact outpoint. No capability is required for structural preservation, and an offered capability may still decline signing. The same-program false-collateral check precedes exclusion by role. Arbitrary collateral scripts remain structurally preserved, without P2WPKH restriction or admission. Step 4 must freeze non-witness bytes, request and verify the admitted P2WPKH sponsor’s signature; only the adopted one-P2WPKH-sponsor envelope can be admitted. Every other collateral row stays structurally preserved, unadmitted and unauthorized. Neither the existing sponsor interface nor `admitted_sponsor_program` changes.

**Production path and provenance.** `packages/transaction/src/keyed_inputs.rs` uses the existing decoder core, checks its canonical re-encoding, computes SHA256d of stripped serialization with the existing digest implementation, compares the selected txid and checks vout. The spending-input flag offer is checked before member authentication: bits outside `0xc0` refuse as `InvalidOutpointFlags`, and every nonzero in-domain byte on either role refuses as `UnsupportedSpendingInputForm`. The encoder cannot serialize either flag, and a peg-in would not spend the bound Elements parent output. At member authentication the crate-private predecessor receipt is minted, but it is retained inside `BoundKeyedInput` only after the remaining member checks, alongside canonical parent bytes, outpoint and decoded output; a refused input exposes no receipt. A capability on a member refuses as `MemberCapability`, since the covenant is signature-free. Nonzero birth positions refuse as an existing-clause construction pre-check. Offered sequence and the accepted zero flag are retained, never described as observed transaction facts. Parent-buffer and capability lifetimes are separate: copied parent buffers may be dropped, while the request borrows only the commitment and capability. The checked `SponsorOffer` snapshot is retained per bound input, including its fee, change and input set; subsequent callback values are not authority for that binding. No inclusion, unspentness, retrieval or finality is established.
