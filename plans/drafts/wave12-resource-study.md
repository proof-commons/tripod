The accepted archive shows acceptance under disclosed zero floors (F10). Relayability under a positive floor is therefore C1's — the sponsored builder, conditioned on `T11-064` and a ruling revisiting ruling 58 — together with a deployment's relay policy.

## 4. Open questions

**OQ1. Whether nonce attempts may stand in canonical bytes anywhere.**

For keeping them out of the resource report's canonical bytes: §14.8 lists "nonce-search attempts as noncanonical diagnostics" and §21 says "nonce attempts and wall time stay noncanonical" (`plans/guides/guide_fourteen.md:2304`, `plans/guides/guide_fourteen.md:3531`). The resource report renders them in its diagnostics.

Against reading those sentences as covering every report: attempts are deterministic — a scan from zero under a fixed budget gives the same count on every run — and the continuity report already renders each side's `rejected_count` and `checked_prefix` in canonical bytes as host-leastness evidence (`packages/vectors/src/maturity_continuity_report.rs:1928–1955`). The same fact is then canonical in one report and noncanonical in the other.

D3 and D5 proceed on the first reading for the resource report and leave the continuity report's leastness facts as that report's evidence. Whether §14.8's clause reaches beyond the resource report is a question about the guide's text.

**OQ2. What an interpreter figure would be compared with if a boundary ever exposed one.**

For equality: §18.3 says a mismatch is any difference, and the linker's totals are exact for the linked program.

Against: the linker's validation budget is "the greatest the linked program can charge rather than what a given spend does" (`packages/linker/src/state_resource.rs:523–529`), while the protocol's figure is the budget a spend used. The linker's peak is main plus alternate, while the protocol reports them apart (F11). Equality is the right test for weight and the wrong one for a maximum.

At this base the question has no subject, because `EG-011` keeps every interpreter figure null. Bite 2 types them not observable at this boundary and compares nothing. The comparison rule for a maximum belongs to whichever change exposes the interpreter.

**OQ3. Whether §18.2's lead cases need their own complete transactions when every width is fixed by encoding.**

For building them: §18.2 says "Measure complete transactions", §18.4 refuses to presume that one transaction maximizes all dimensions, and F9's equality is a reading until a measurement shows it.

Against: the figures are expected to equal the interior candidate's except for nonce attempts, so building adds construction code for one moving number.

D1 proceeds on building them, because the equality is itself a result the report can state only once measured. The equality also makes the nonce corpus's lead derivations the one place the cases differ. Whether the guide meant a separate transaction per case even where encoding fixes every width is a question about its text.
