## Sponsor change · `sec:s8c:sponsor`

packages/transaction/src/keyed_fixed_sponsor.rs owns keyed_fixed_sponsor_digest/digest_core and verify_keyed_fixed_sponsor/verify_core. Change only digest_core's output-form predicate and the associated documentation/refusal description: outputs must retain explicit assets, but may carry explicit values or validly encoded value commitments and null or validly encoded present nonces. Keep explicit(spent) for the authenticated sponsor parent, empty scriptSig for every input, stripped canonical round-trip, ordinary witness-v0 key-hash program, selected input bounds, strict DER/low-S/compressed pubkey and SIGHASH_ALL. Signature production remains delegated; this owner verifies, it does not sign. Confidential sponsor spent values/assets/nonces, asset commitments on outputs, issuance, peg-in, alternative hash flags and malformed/witness-bearing frozen bytes remain refused at their existing boundary. Supporting a non-null output nonce does not make S6's constructor accept present-nonce member parents.

The existing TargetOutput::encode already serializes asset/value/nonce/program exactly, and hashOutputs in digest_core already hashes that ordered serialization. TargetTransaction::decode_core handles the selected hybrid confidential-value form; its output_witness reader continues to reject surjection proofs. These owners are read-only. Retain the existing SegWit-v0 preimage order, explicit spent amount and null issuance bytes; no digest recipe changes for explicit-only transactions. Compare the digest independently with elements::sighash::SighashCache::segwitv0_sighash in the vectors proof/sponsor test, using the precedent at packages/vectors/tests/keyed_reproduction/fixture.rs, and replay every selected campaign3 signature through the extended owner. Vectors already has the Elements dependency; transaction's surface test covers its domain boundary without adding that dependency. The 220 complete retained records, plus supporting payment signatures, are the regression domain; the 4,000 archive-addressed supporting rows are not silently promoted to a new offline replay claim.

Output witnesses, including range proofs, are not in this signature message. A valid combined proof/tally/sponsor control is checked as three separate predicates over one transaction: range proofs against exact commitments, asset and script; commitment balance including fee and authenticated inputs; sponsor signature against frozen non-witness bytes. Changing only a range-proof byte leaves the digest/signature valid but fails the proof verifier. Changing a committed value or present nonce while retaining the signature changes hashOutputs and must fail InvalidSignature when all earlier forms remain valid. This is signature binding, not proof of transaction validity. Test an explicit sponsor parent beside a committed-value sponsor parent to demonstrate the still-refused UnsupportedForm boundary. Retain native confidential-value refusals separately from these local cryptographic results.

## Reusable historical source mechanism · `sec:s8c:history`

The current reconstruct_campaign_freeze in keyed_fixed_manifest.rs recognizes two source paths, today's remaining bytes and four campaign identities; encoding::decode fixes the source count at 98. S8c changes nine pinned sources, so it must replace those assumptions in the same reviewed, gate-passing unit as the sponsor change. Extend these existing owners, pins.rs's reviewed anchors and the test-only keyed_fixed_corpus/fixture.rs source loader; do not add a second freeze parser or a generic history service.

Each reviewed capture epoch has an immutable ordered source map (path and digest), expected source count, admitted recipe/schema/target/computed inventory/envelope, and a closed list of per-triple encoding identities. Epoch selection comes from the corpus's checked fixture index and independently reviewed anchors in pins.rs, never solely from an offered encoding. Current native capture still uses offer/validate. Historical admission decodes against the selected epoch's count/encoding bounds, authenticates the exact ordered map, reconstructs the descriptor, checks envelope/codes and byte-for-byte re-encoding, then compares the epoch's exact per-triple identity. The grammar and recipe remain unchanged; an unknown epoch, foreign identity or unsupported recipe refuses. Preserve the campaign3 list; The failed S8c epoch retains its distinct list for K=42 with policy A and values 60, 17 and 18; the corrected capture has a separately reviewed v=60 list, plus the existing independently anchored legacy freeze for the old-leaf semantic identity. The fixed-form 60 encoding names the S8c capture instrument for the legacy packet, not an assertion that the old leaf implements the fixed-form triple.

Source snapshots are addressed by the pair (path, digest), not path alone. Preserve the original campaign3 versions of manifest.rs and encoding.rs and add the pre-S8c bytes of every changed pinned source; the two manifest/encoding paths can have multiple historical versions. Keep this in the existing sources.json.lzma with the same bounded file-pair container, using version-qualified source-history names and an explicit logical path/digest catalog in the checked census. Migrating this source-only projection changes no captured source byte. For each required epoch row, use retained bytes of that exact pair, or compiled current bytes only if their computed digest equals the required historical digest. Never fall back merely because the path exists today. Paths removed from current inventory remain resolvable from snapshots; added current paths cannot satisfy old rows. Reject duplicate pair keys, malformed names, wrong snapshot digests, missing required rows and catalog entries not authorized by the reviewed history maps. Keep snapshots shared between epochs without allowing cross-fixture path overwrites.

Pass the independently selected epoch's source count to the decoder and bound every frame before allocation; do not take the allocation bound from the packet's advertised count. The selected S8c inventory remains 98 and computed codes remain 15: all nine edited sources are already pinned, and the new offline consumer child is deliberately unpinned. A future reviewed inventory transition adds its own exact map/count/identities and snapshots without rewriting the resolver. A different encoding recipe or descriptor semantics still requires its own admission; parameterizing source history grants no automatic recipe compatibility. Keep existing current validation strict. The regression controls admit all four campaign3 encodings after S8c's re-pin, admit S8c under its own anchors, and refuse missing/changed historical sponsor bytes, a cross-epoch identity, an unreviewed source count or an unknown snapshot.

The paired history entry records each of the nine paths, old/new digest, full source diff, behavior/editorial classification and affected evidence. This is a behavioral sponsor and capture-harness re-freeze, not an editorial update. It reopens sponsor admission, current producer/source identity, capture census/outcome/control/waiter behavior and historical consumer equivalence. The exact campaign3 fixtures, original four identities, 220-record admission, seven model attributions, six histories and native scaling/policy observations remain standing only with successful replay and unchanged premises; no historical identity is rewritten. Explicit-only digest equivalence is mandatory. Any disagreement reopens affected evidence instead of being fixed by new pins. Legacy pins, legacy producer bytes and legacy captures remain unchanged.

## Driver, bounds and seal · `sec:s8c:driver`

Extend the existing capture-unit.sh owner with --campaign and --wait-campaign modes; do not create another runner. The operator supplies a clean reviewed CHECKOUT, full REVIEWED_COMMIT, unique RUN and the immutable IMAGE from the original baseline. Proposed invocation, after the implementation review and gate, is `systemd-run --user --quiet --collect --same-dir --unit="tripod-$RUN-campaign" --property=RuntimeMaxSec=6060 bash "$CHECKOUT/scripts/keyed-fixed-capture/capture-unit.sh" --campaign "$CHECKOUT" "$REVIEWED_COMMIT" "$RUN" "$IMAGE"`. Its foreground waiter is `bash "$CHECKOUT/scripts/keyed-fixed-capture/capture-unit.sh" --wait-campaign "/var/home/tripod/loops/evidence/fixed-form/$RUN"`. These are operator commands to be implemented/reviewed, not commands this documents lane runs.

One detached unit owns preparation, sponsor and legacy-copy sequentially; it never launches separate preparation/family systemd units. --campaign runs capture-prepare.sh synchronously with the selected S8c family list, then the existing family run logic for sponsor and legacy-copy in order, with fresh containers. Extract the existing settled-family seal logic into a function in capture-unit.sh so the parent seals after the child writer exits and container absence is verified, without querying a nonexistent family service. Run-one selects exactly native_sponsor or native_legacy_copy; those are ignored in ordinary gates. Keep the process-wide filtered subscriber and proportional exchange timing byte/line checks delivered by ruling 220, including phase completion for the legacy path, which currently returns early. No second subscriber in the same process is needed because each family uses its own test process.

Use 2100 s preparation guard; for each family retain 600 s executor, 1800 s container guard and 120 s cleanup/seal allowance. One unit allows 2100 + 1920 + 1920 + 120 = 6060 s. Expected warm preparation is 150–300 s from the prior 248 s measurement; nine submissions/27 exchanges and local proof work suggest 15–45 s sponsor and 10–30 s legacy-copy, plus 10–30 s sealing: 185–405 s total, explicitly an estimate. At 45/30 s the 600 s executor guard exceeds fourfold, but the completed run must report measured headroom and load/cgroup scope. A breached guard or fourfold condition is a finding; no automatic retry, increased bound or extra family is selected. No new scaling capture is justified by this work.

The parent records a retained start/deadline, service/PID, per-phase exit, command and logs; its waiter follows that same unit and deadline across reconnects and through awaiting-start. On terminal service state, reread prepare.log before classifying a missing preparation marker: a marker appended between the first read and the state query must count. A genuinely missing/nonzero/duplicate marker refuses. The synchronous preparation return, exact successful marker and root/build seal must agree. Preserve failed-run evidence and verify writers/containers absent before sealing. Each family seal includes exact records, exchanges, proofs/parents, CENSUS, timing and resource scope. A separate campaign-retention.sha256 completion seal includes both family seal digests and the unchanged preparation root/build seals; emit one KFF_CAMPAIGN_DONE run=... exit=0 only after those seals exist and all exits are zero. The append-only driver log/end marker is explicitly outside its own seal, avoiding self-hashing. A terminal failure may seal settled bytes but emits no success marker. The foreground waiter does not return success on a dead transport or missing marker.
