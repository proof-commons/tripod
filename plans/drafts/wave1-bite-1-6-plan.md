**Disposition (Adopted sequence and decisions)** · `rec:w1b16:adoption`

The six-step sequence and three recommendations are adopted for bite 1.6, with the supplied-key requirement and controls below. This disposition governs implementation; the proposals retain their reasoning. This plans-only adoption runs no native capture.

**Supplied-key requirement.** The bundle is one reviewed template with a single key-data occurrence. A supplied 32-byte key instantiates it; leaf, output program, commitment, control data and handle sets are computed per key. Every 32-byte value is canonical key data, with no scalar or coordinate interpretation. Under the same template, target, policy and envelope a new key needs no new review or campaign; its per-instance checks and premises still run and are never inherited from another key. Changing those frozen conditions reopens affected evidence. The reason is the fixed-width key push, dropped before either clause: neither clause branches on its value. Pinning the delivered bundle to a fixture key would turn each use into unnecessary re-certification. Consistent authenticated substitution, not changing a key while retaining another key's predecessor, is the generic argument.

(`q:w1b16:key-domain`) is adopted: schema 1 keeps its total typed outcome. A hash-derived tweak at or above the group order, or a tweaked point at infinity, returns the existing typed error; the caller supplies another key. Nothing is silently rehashed, reduced or retried. These exceptional outcomes have negligible probability for a key not chosen to produce them, as in an ordinary key-tweak construction; silently repairing them would change the reviewed function. Refusal belongs to that function and needs no per-key review. Closure states “any 32-byte key is accepted as data; commitment succeeds or refuses by one reviewed rule”, never success for every key. Handle-set separation across keys remains conditional on the named cryptographic premises.

**Second key.** Fix the exact public ASCII phrase `Tripod Wave 1 supplied-key independence control`. Step 1 computes SHA-256 of exactly those ASCII bytes, without quotes, newline, NUL terminator or other framing, and pins the 32-byte digest as the second key. The phrase is fixed here before any fixture for it exists; no digest or fixture is generated by this adoption. A public rule fixed before generation cannot be selected to suit generated fixtures and needs no secrecy ceremony.

(`q:w1b16:capture`) is adopted: native captures run on kranich in the retained native image with the pinned executable, framework, executor and protocol, on a fresh isolated regtest chain after handshake/provenance verification; drift stops capture. Each capture is a separate ignored target with its own pilot-derived hang guard, started as its own unit, with all listed retention under one unique run directory. Kranich is the node of record with the pinned toolchain already built and proved. A capture never implicit in a gate cannot be mistaken for a gate. Exact dispatch commands and paths remain required before launch.

(`q:w1b16:measurements`) is adopted: unavailable instrument dimensions stay absent; no model counter becomes a native figure. Wall, CPU and stalls require an identified scope. Step 6 explicitly disposes the Wave-0 baseline regression question from retained comparable figures first, using targeted profiling only if a delivery regression remains unexplained; any new build-cost comparison first requires the runner's cgroup-identity repair. Absence is a fact about the instrument, not a license to invent a subject measurement.

**Reviews.** Independent review follows step 1 (generic argument, freeze manifest and two-key controls, before capture), step 2 (bridge and subject provenance), steps 3 and 4 together if landed close together, otherwise each (boundaries, endpoints, fee and policy evidence), step 5 (independent reconstruction, joins and resource units), and the step-6 packet before a separate closing disposition.

**Test time.** Offline subjects retain the reviewed 40-second subject and 300-second family hang guards and split-or-report rule. Native captures are never fitted into those bounds. The plan's wall allowances are planning figures, not limits.

**Closure scope.** Wave 1 may claim one parameterized reviewed realization with conditional authentication and per-instance evidence, observed natively under two representative keys. It may not claim successful commitment for every key, proof of cryptographic separation, deployment finality or quantities the instrument cannot observe. If a wave gate requires more, reopen and decide it before closure rather than satisfy it by wording.

## One template, supplied public keys · `sec:w1b16:keys`

**Bundle identity.** Freeze once the declarations and key-free symbolic plans, proof/placement selection, 16-instruction leaf grammar, schema-1 constructor/control function, target/ABI, dependency versions, funding/signing separation and measured policy envelope. Freeze the template's sole key-data occurrence: canonical push32, bytes 1–32, followed by DROP. Emission instantiates that occurrence once. The linker accepts the completed grammar with zero mandatory byte relocations; adding a second key relocation would contradict (`rec:w1b14:link`). “Relocation site” here means template substitution, not a new linker parameter or hash fixed point. Per key compute the leaf, leaf hash/root/tweak, output program/parity/control, commitment, request association and authenticated handle sets. Requests already take the supplied key (`packages/transaction/src/keyed_request.rs`); it is symbolic plans and declaration laws, not concrete requests, that omit key values. Keys are public data, not secrets or signing keys. This instantiates the key fixed at covenant generation in (`[A-def:kpc-model:keyed-membership]`), without freezing one fixture value as the template’s identity.

**Generic argument and its limits.** `packages/tapscript/src/keyed_constructor.rs` admits every 32-byte value, including zero: no scalar, nonzero or x-coordinate interpretation applies to the semantic key. The push has fixed length and is dropped before either clause; no clause branches on its contents. The unchanged suffix, stack shapes, operation counts, element widths, script/control lengths and per-member 88/91/255 byte/weight formulas therefore hold for every successfully committed instance. Clause semantics are equivariant under consistent substitution of authenticated programs, not under changing a key while keeping an old predecessor. Concrete signatures, transaction identities, commitment hashes, runtime/CPU and relay outcomes are not constant across keys. Neither sizes nor finite samples prove constant native cost.

`packages/vectors/tests/keyed_constructor/mod.rs::canonical_key_literal_is_data_before_both_clauses`, `distinct_semantic_key_changes_only_literal_and_dependent_commitments`, and `packages/linker/tests/keyed_bundle.rs::public_keyed_link_preserves_two_keys_three_scopes_and_offer_permutations` already support the argument. The standard-library model's key-indexed identities support separation independently. Disjoint authenticated program families remain conditional on cryptographic assumptions, not proven injectivity. Each key recomputes membership, inclusion/exclusion of consumed handles and deployment premises; another key's observations confer none of those facts.

**Current fixed values.** No inspected production entry requires a source edit to accept a different semantic key. The reproduction fixture fixes 32 repetitions of byte 42; constructor controls use K/L; funding/scaling tests use 32 repetitions of bytes 0x45 and 0x47 respectively. Old archive admission pins intentionally name those exact subjects. `KeyedRecipes::new` and scaling planners already accept key parameters, but the native staging modules build prototype transactions, not the sealed final public request/construct pipeline. Step 1 supplies a separate parameterized fixture factory; step 2 supplies a final-form conformance adapter. Preserve every old literal, pin and archive reader; no regeneration or new key-dependent production branch is proposed. Fixed equality-op offsets are grammar facts, not key values; bind them to the grammar instead of moving them with keys.

**Key controls.** Predeclare an additional 32-byte key from an independently published public choice, with its source retained before fixture generation; no secret ceremony. Run identical graph/subject schemas under the old control key and that key. Independently predict canonical prefix + key + suffix, then hashes/parity/control/program through the first-party conformance arithmetic; compare production construction and fresh-process reproduction. Add zero, all-ones and high-bit keys, wrong-width input at any textual campaign boundary, nonminimal push encoding at authentication, and mixed-key member/successor refusals beside passing members. All 32-byte values are canonical data; noncanonical *encoding* is distinct. Generic proofs run once; actual commitment/reconstruction and a–f final-subject observations run for both representative keys, including worst-envelope endpoints. No future campaign is required merely for a new supplied value under the same reviewed template and conditions; its per-instance checks still run. Changed template, target, policy or envelope reopens affected measurements.

**Decision: totality** · `q:w1b16:key-domain`

Recommend retaining schema 1's total typed outcome, not promising successful commitment for every 32-byte input: a hash-derived tweak at/above the group order or an infinity sum has an existing typed refusal. Do not silently rehash, reduce a scalar or reject a semantic key as a signing-key value. This supports one reviewed algorithm for any supplied key without new review; universal successful construction and unconditional collision-free separation cannot be promised inside Wave 1. If “any key” requires success even for these exceptional arithmetic outcomes, it needs a new recipe decision and remeasurement before freeze, not an evidence-only patch.
