# Tapscript tracing engineering design

## Purpose and shape · `sec:tracing-tapscript:purpose`

`tapscript` is a library adapter from compiler-owned target requirements to the reviewed Elements Tapscript contract. It assesses capabilities and evidence, builds typed programs and candidate compact, live, and STATE constructions, validates abstract execution, and returns typed refusals and outstanding obligations. It has no binary, command runner, or process stream owner.

`src/lib.rs` re-exports assessment (`capability.rs`, `operation_assessment.rs`, `maturity_assessment.rs`), script representation and abstract execution (`instruction.rs`, `program.rs`, `stack.rs`, `error.rs`), compact construction (`pattern.rs`, `shape.rs`, `bundle.rs`, `policy.rs`, `authorization.rs`), live transfer (`live_*.rs`), and STATE construction (`state_*.rs`, `operator_authorization.rs`). `upstream.rs` carries compiler-facing vocabulary, and `src/tests/` plus `tests/` exercise the public boundaries.

`compiler`, `realization`, and `target-elements` provide typed inputs and target facts. `linker`, `transaction`, `vectors`, and `target-elements-conformance` consume this library's candidates, programs, or refusals; they retain responsibility for their own linking, transaction, evidence, and command boundaries. A candidate is not an observed target acceptance, and an outstanding obligation is not discharged work.

## Standard output and standard error · `sec:tracing-tapscript:streams`

The library writes neither process stream and never installs a subscriber or panic hook. Typed `TapscriptProgram`, assessment, candidate, refusal, and nonce-evidence values remain authoritative returns; tracing events cannot replace or change them. A first-party executable that publishes a result uses the shared command setup for one JSON object plus a newline, documented NDJSON, or an explicit asset path, with empty stdout before publication failure, terminal refusal for stdout results, and the established exit classes (`[ADR010-rule:output:streams]`, `[ADR010-rule:output:json]`, `[ADR010-rule:output:tty]`). Tapscript adds no stdout schema.

For executable callers, the shared startup is `cli_common::install_command_subscriber(command_name)` as the first statement: it installs the process's one JSON subscriber and panic hook before parsing. Its unfiltered `cli_common::control` route emits help, version, usage, TTY-refusal, and panic records in the established ADR-010 wire shape; its reloadable diagnostic route emits other tracing records. Both routes use one locked stderr writer. Before parsing, diagnostics use a nonempty `RUST_LOG` or `info`; after parsing, the runner applies nonempty `RUST_LOG`, then `--debug`, then its default, with an invalid directive falling back to `info` and a value-free WARN event. Control records survive `RUST_LOG=off`; the panic path is best effort, nonblocking, and emits at most one record without disclosing an early payload.

The diagnostic JSON envelope contains target, level, fields, and the current span list. Each enabled span emits one close record with name, target, level, entry fields, `busy_ns: u64`, and `idle_ns: u64`; there are no open or enter records. A runner owns an INFO command span and one terminal command outcome: INFO completion or ERROR failure, while usage and TTY refusal have only their control record. Tapscript's DEBUG typed refusal is an observation within that parent, not another terminal diagnostic. Libraries do not copy `command`, `output_mode`, `exit_class`, or `result_published` into their events.

The shared subscriber produces every first-party stderr byte, including early control records emitted before parsing; ADR-010 retains their JSON schema and safe early fields. Its stream contract routes `execwrap` child bytes only to explicit files and has no child-byte relay exception. Tapscript has no process stream path to migrate: its library events remain typed observations, and executable owners test their own subscriber output in subprocesses (`[ADR010-rule:output:streams]`, `[ADR010-rule:output:diagnostics]`, `[ADR010-rule:output:implementation]`).

## Spans · `sec:tracing-tapscript:spans`

Every target is an explicit literal using the library crate stem and owning module; a span's name is an unprefixed lower-snake-case operation. INFO marks a bounded outer operation, DEBUG a potentially repeated operation or phase. Entry fields are cheap scalar context only, with no outcome or completed count on the span. The subscriber's close record measures inclusive duration; nested durations are not summed as independent wall time (`[ADR026-dec:tracing:core]`).

| `assess_requirements` | `tapscript::capability` | DEBUG | `requirement_count: u64` | Target requirement and evidence projection in `src/capability.rs:1175` can recur inside larger work. |

The public `validate_program` wrapper and bundle or constructor operations call an uninstrumented validator core when they compose within this crate. The same pattern applies wherever one Tapscript public operation calls another: an external call produces one owned completion event rather than duplicate same-crate propagation events. A call into another crate still yields that crate's own event under its span.

## Events · `sec:tracing-tapscript:events`

Each instrumented public operation emits one completion event inside its span when it returns. `outcome: &'static str` is `completed` for a returned typed result (even one with a negative verdict), `refused` for an expected typed refusal, or `failed` for an operational/internal error. A refused event always has `refusal_kind: &'static str` from a stable, payload-free snake_case variant name and is DEBUG regardless of its span tier; a failed event has `error_kind: &'static str` and uses its span tier. The command boundary owns the single fatal ERROR if a returned failure ends the command. This crate proposes no recoverable anomaly that warrants WARN and no unreturned invariant or data-loss failure that warrants a library ERROR.

| Operation target | Completed event and level | Completed fields (all counts `u64`) | Refused event and fields |
|---|---|---|---|
| `tapscript::stack` | DEBUG `program validation completed` | `outcome`, `visited_state_count`, `success_path_count`, `failure_path_count`, `abort_path_count` | DEBUG `program validation refused`: `outcome`, `refusal_kind`, `visited_state_count`; add no partial result. |
| `tapscript::capability` | DEBUG `requirements assessed` | `outcome`, `requirement_count`, `supported_count`, `unsupported_count`, `evidence_count` | DEBUG `requirements refused`: `outcome`, `refusal_kind` if the public boundary returns a typed refusal. |
| `tapscript::operation_assessment` | DEBUG `operation assessed` | `outcome`, `verdict_count` | DEBUG `operation assessment refused`: `outcome`, `refusal_kind`. |
| `tapscript::bundle` | INFO `candidate bundle emitted` | `outcome`, `family`, `leaf_count`, `relocation_count`, `script_bytes`, `outstanding_obligation_count` | DEBUG `candidate bundle refused`: `outcome`, `family`, `refusal_kind`. |
| `tapscript::live_bundle` | INFO `live candidate bundle emitted` | `outcome`, `family`, `leaf_count`, `relocation_count`, `script_bytes`, `outstanding_obligation_count` | DEBUG `live candidate bundle refused`: `outcome`, `family`, `refusal_kind`. |
| `tapscript::live_constructor` | DEBUG `live constructor assessed` | `outcome`, `family`, `leaf_count`, `outstanding_obligation_count` | DEBUG `live constructor refused`: `outcome`, `family`, `refusal_kind`. |
| `tapscript::state_constructor` | INFO `state nonce search completed` | `outcome`, `family`, `attempt_count`, `rejected_nonce_count` | DEBUG `state nonce search refused`: `outcome`, `family`, `refusal_kind`, `attempt_count`, `rejected_nonce_count` when known. |
| `tapscript::maturity_assessment` | DEBUG `maturity announcement assessed` | `outcome`, `record_count`, `verdict_count` | DEBUG `maturity announcement refused`: `outcome`, `refusal_kind`. |

The stack's path counts are cardinalities of the distinct returned terminal alternatives: successful and nonaborting-failure abstract states and abort causes; they do not count every concrete execution path. `visited_state_count` is the existing budgeted visit tally. In capability assessment, `supported_count` counts capability dispositions other than `Unsupported` and `MissingTargetPrimitives`, while `unsupported_count` counts those two; these are static projection categories, not a claim that outstanding evidence is complete. For compact and live bundles, `outstanding_obligation_count` counts the constructor's explicit outstanding lifecycle requirements, not completed checks or the separate resource-dimension map. For STATE search, the aggregate attempt and rejected-nonce counts come from the bounded scan and retained evidence; there is no per-nonce event or selected-nonce field. `MaturityAssessmentSet` holds verdicts but not the separate carrier projection, so maturity `verdict_count` sums its representation verdict maps and does not claim carrier derivation. A refusal that occurs before a count exists omits that optional count rather than inventing a value.

## Naming · `sec:tracing-tapscript:naming`

Targets are literal `tapscript::<module>` strings, not default module paths that can change with a move or a binary crate. Span names are lower-snake-case operation verbs without a package prefix or dots, and event messages are fixed short lowercase phrases; their text is never a machine key. Fields have static lower-snake-case names. `family` is the closed `compact | live | state` vocabulary on flow-specific work; generic validators do not invent a family. Where one architecture operation is already identified, `operation_code: u16` is its typed code; no generic `operation` field duplicates the span name.

Cardinalities end in `_count: u64`, with `usize` converted saturatingly at emission, byte totals end in `_bytes: u64`, and configured bounds end in `_limit: u64`. `outcome` is exactly `completed | refused | failed`; `refusal_kind` appears exactly for `refused` and `error_kind` exactly for `failed`. `phase` is a fixed step such as `validate` or `publish` only when the span name does not already say it. Tapscript never sets `standing`, which is reserved for observed `accepted | refused | unobserved` test evidence; an observed refusal's variant is the evidence owner's `observed_refusal_kind`, not this library's `refusal_kind`.

No tracing field contains a script, witness, key, nonce, metadata, amount, hash, result or error rendering, caller-supplied path, argv, child output, transaction weight, or report body. Static role names and aggregate counts are sufficient for this package. Cross-package correlation uses parent spans and already-held safe `family` or `operation_code`, with no new span ID or correlation ID. Command fields belong to `cli-common`; paths and rendered explanations are limited to a checker-owned located diagnostic, which Tapscript does not emit (`[ADR010-rule:output:data-classification]`).

## Cost · `sec:tracing-tapscript:cost`

Entry fields read existing scalar values or collection lengths; requirement iterators are traversed only under `tracing::enabled!` because their size is not directly exposed. Result-set counts, lifecycle counts, and rejected-nonce length are read after the operation has already produced them; `total_script_bytes()` traverses leaves, so compute it only when the INFO event is enabled. Do not encode a script, clone a set, format an error, derive a hash, search a second time, or traverse a result solely to fill a disabled field. Use `tracing::enabled!` or lazy formatting for an optional derived value; static refusal names and checked or saturating integer conversion do not change an operation's result. Existing visit and nonce-budget counters remain because they govern correctness and evidence.

No production `Instant` measures telemetry. The subscriber emits `busy_ns` and `idle_ns` on enabled span close by default, with INFO spans visible in the default diagnostic filter and DEBUG spans available when requested. Parent durations are inclusive; a collector uses parentage for exclusive attribution rather than adding nested walls. There is no measured-duration event field or per-item progress in this library. If a future operation has slow visible units, use bounded milestone events with `completed_count: u64` and `total_count: u64`, INFO only for few slow units and DEBUG otherwise.

## Testing · `sec:tracing-tapscript:testing`

The package inherits `tracing-subscriber` as a dev dependency and uses a package-local capture subscriber. Each test that captures records re-executes itself as the only selected test in a fresh child process, using its exact harness path and a child marker; the parent requires a successful exit and exactly one passed test, reporting child output on failure. This isolates callsite-interest changes made by unrelated parallel harness tests. Within the child, one process-wide install mutex covers the whole capture, an uninstalled test-only `Dispatch` anchors callsite interest, and the capture rebuilds tracing's callsite interest cache inside `tracing::subscriber::with_default` before running the subject. The anchor is never set as a default and receives no records; actual assertions use only the scoped subscriber. Tests record event and close-record metadata and typed fields in memory, and assert target, level, span name, fixed message, and field values without checking duration magnitude or order across threads. A regression touches one callsite without capture, then captures it from two threads and requires one span in each capture. A thread that performs instrumented work explicitly carries `tracing::dispatcher::get_default(Dispatch::clone)` into its own `with_default` scope and enters the parent span; no test installs a global subscriber or needs a shared helper crate.

Test an accepted control and a subject one coordinate away that returns a typed refusal at `validate_program`, compact or live bundle emission, and the STATE nonce-search boundary. Each external call emits one owned event; each refused event is DEBUG with `refusal_kind` and no WARN or ERROR. A nested bundle-to-validator case asserts exactly one Tapscript event for the external call. Compare returned values, refusal variants, and produced bytes with and without the capture, and assert that event fields contain no script or witness bytes. Test code writes no process stream; deterministic observations become assertions.

A source-table audit checks every literal returned by the five tracing refusal-name tables against the snake_case field vocabulary and pins standalone `a` segments. `StateConstructorRefusal::name()` remains a separate established hyphenated diagnostic vocabulary; tracing `refusal_kind` uses the snake_case variant name.

Tapscript has no binary stdout contract to test. Executable owners use subprocesses to verify JSON stdout or explicit assets, empty stdout before failure, control records even with `RUST_LOG=off`, panic and TTY records, and one enabled INFO span close record. The process-global bootstrap, control route, panic hook, and actual stderr writer are not tested by installing a global subscriber in a library test. Ordinary harness tests remain outside ADR-010's executable scope; a harness-free program consumed by another program follows the executable contract.

## Implementation plan · `sec:tracing-tapscript:implementation`

1. `refactor(tapscript): isolate internal validation cores` — separate external public wrappers from uninstrumented same-crate cores for program validation and composed operations, add package-local scoped capture support and stable refusal-kind helpers; this is a library commit and does not wait for `cli-common`.
2. `feat(tapscript): trace stack and assessments` — add the DEBUG spans and one completion event to program validation, requirement and operation assessment, including saturating aggregate counts and control/refusal tests; this uses only the existing core tracing dependency and the local test helper.
3. `feat(tapscript): trace compact and live candidates` — add bundle and live-constructor spans and completion/refusal events with `family`, resource and outstanding-lifecycle counts, and nested-call tests; coordinate names with `linker`, which may independently nest its own span over these calls.
4. `feat(tapscript): trace state search and maturity assessment` — add one aggregate nonce-search event, STATE and maturity spans, refusal-kind tests, and no per-attempt telemetry; retain exact returned nonce evidence and constructor behavior.

These four library commits require no command bootstrap and contain no executable migration. The shared `cli-common` subscriber and ADR-010 stream contract are implemented: executable owners use the pre-parse bootstrap and subprocess assertions, while Tapscript owns no binary-level stderr assertion. `cli-common` retains compatibility delegates for legacy callers; removing them and adding the workspace direct-stderr lint belong outside this package.

## Open questions for the other packages · `sec:tracing-tapscript:open-questions`

- The target convention is resolved to literal crate-stem module paths; `tapscript` owns no subscriber and no package-specific command target.
- Local results use `completed | refused | failed`, with expected typed refusal at DEBUG and `refusal_kind`; the command boundary alone emits a fatal ERROR for a returned error. A candidate's completed construction never claims observed acceptance.
- Compact, live, and STATE work uses the shared `family` labels and parent spans for correlation; safe `operation_code: u16` is used only when already held, while scripts, witnesses, keys, metadata, paths, and nonce values stay out of fields.
- `cli-common` owns the pre-parse subscriber, unfiltered early control records, panic-safe path, filter reload, and ADR-010 stream implementation. Tapscript owns library instrumentation only; each executable owner tests its own streams.
