# Labels tracing engineering design · `sec:tracing-labels:design`

## Purpose and shape · `sec:tracing-labels:purpose`

`tripod-labels` parses owner-local labels and imported citations, harvests TeX, Markdown, Rust and script sources into ordered registries, verifies the declared repository census and generated publications, and checks plan structure, tracked-file modes, forbidden text and hash-citation claims. Pure parsers, graph operations and renderers sit beside filesystem-facing `census`, `repository`, `check` and `plans` modules; the public `LabelDiagnostic` and report types keep defects and results as typed data.

Seven binaries wrap that library: five non-writing checks (`check-labels`, `check-plans`, `check-hash-citations`, `check-forbidden-text`, `census-audit`) and two register generators (`generate-label-registers`, `generate-attestation-register`). `packages/artifacts/src/lib.rs:47,92,160` consumes `RepositoryCensus` and `model_labels_json`; Meson targets and `scripts/check-plans.sh` call the binaries. Checks can return a complete negative report to their binary without changing acceptance, while generation can return `GenerateError::Validation` or an operational publication failure.

## Standard output and standard error · `sec:tracing-labels:streams`

The five checks retain one JSON object plus newline on stdout after a successful direct-mode check, or a report asset plus success stamp with empty stdout in build mode. The two generators publish argument-named assets and leave stdout empty. Pre-publication failure leaves stdout empty, a partial write can leave a prefix, and direct-mode result commands refuse terminal stdout. Report schemas, generator bytes and exit classes stay as specified by (`[ADR010-rule:output:streams]`), (`[ADR010-rule:output:json]`), (`[ADR010-rule:output:assets]`) and (`[ADR010-rule:output:tty]`); labels captures Git child output and never relays it to either parent stream.

Every first-party stderr record comes from the process's one `tracing` subscriber. Each labels binary's first statement calls `cli_common::install_command_subscriber(COMMAND_NAME)`, which installs that subscriber and the JSON panic hook before clap parsing; the library installs neither. The shared subscriber has an always-enabled `cli_common::control` route for byte-identical ADR-010 help, version, usage, TTY, panic and status records, and a reloadable diagnostic route; both use one non-interleaving locked stderr writer. Required control records survive `RUST_LOG=off`; the panic hook makes at most one best-effort record through a nonblocking lock and exits 1. Before parsing, the diagnostic filter is nonempty `RUST_LOG` or INFO; after parsing, the runner reloads it with nonempty `RUST_LOG`, then parsed `--debug`, then the command default. An invalid directive falls back to INFO and emits one WARN `filter directive rejected` event without echoing the value. No binary holds the reload handle or installs a second subscriber.

The diagnostic route retains JSON records with `timestamp`, `level`, `target`, `fields`, `span` and `spans`; the control route retains the ADR-010 `schema`, `command`, `kind`, `message` and optional typed fields. `cli-common` emits one INFO `command completed` or one ERROR `command failed` terminal event after execution; usage and TTY refusal end with only their control record. Its INFO `command` span encloses each binary's closure and result publication after parsing. Labels installs the shared subscriber directly at startup.

ADR-010 requires subscriber-produced stderr, has no raw child-byte relay exception for either stream, keeps explicit JSON stdout results and the control wire schema, and treats harness-free programs and test-subject binaries as first-party executables for stderr. `execwrap` routes child stdout and stderr only to explicit files and refuses an unrouted stream before spawning; labels itself has no relay. Labels has no direct standard-stream diagnostic writes, and its seven binaries use the shared subscriber and runners under this contract (`[ADR010-rule:output:streams]`) (`[ADR010-rule:output:early-startup]`).

## Spans · `sec:tracing-labels:spans`

Every target below is an explicit literal rooted at the `labels` crate stem; names are snake_case and span fields are cheap entry context only. The shared `cli_common::command` INFO parent spans binary invocations, and the shared `cli_common::publication` `publish_batch` span measures register publication with one completion event and a DEBUG `stage_asset` event only for a changed asset, so labels adds neither a second command span nor a batch wrapper. The subscriber writes one close record for each enabled span, with name, target, level, entry fields, `busy_ns: u64` and `idle_ns: u64`; there are no open or enter records and no measured-duration event. Nested durations are inclusive and must not be summed as separate wall time.

## Events · `sec:tracing-labels:events`

Each instrumented public operation emits exactly one completion event inside its span, including on a typed refusal or operational failure. When one public labels operation calls another, it uses an uninstrumented internal core so the outer call does not duplicate that inner public completion; a direct external call still gets its own event. `outcome: &'static str` is only `completed`, `refused` or `failed`: a complete check that found defects is `completed` with `valid = false`, while `refused` means a typed refusal prevented completion. A completed event uses its span's tier, a refused event is DEBUG, and a failed library event uses its span's tier with `error_kind`; the runner alone emits the terminal command ERROR. The reports retain their own `valid` verdict and all per-kind totals.

| Event and owner | Target | Level | Fixed message | Fields (types) |
|---|---|---|---|---|
| Repository check return | `labels::check` | INFO | `label check completed` | `outcome: &'static str` (`completed`), `valid: bool`, `source_file_count: u64`, `diagnostic_count: u64` |
| Direct source harvest return | `labels::repository` | DEBUG | `source harvest completed` | `outcome: &'static str` (`completed`), `source_file_count: u64`, `diagnostic_count: u64` |
| Direct census verification return | `labels::census` | DEBUG | `census verification completed` | `outcome: &'static str` (`completed`), `group_count: u64`, `defect_count: u64` |
| Plan check return | `labels::plans` | INFO | `plan check completed` | `outcome: &'static str` (`completed` or `failed`), `valid: bool`, `warning_count: u64` and `failure_count: u64` when a report exists; `error_kind: &'static str` (`environment`) only on failed |
| Tracked-tree scan or audit return | `labels::hashcite`, `labels::forbidden`, `labels::census` | INFO on completed or failed; DEBUG on typed refusal | `tracked audit completed` | `outcome: &'static str`, `valid: bool` when a report exists, `scanned_file_count: u64` where known, `refusal_count: u64` where known; hash audit also `rule_count: u64`, `idle_rule_count: u64`; failed only: `error_kind: &'static str`, `child_exit_code: i32` when a child exited |
| Register generator return | `labels::repository` | INFO on completed or failed; DEBUG on typed refusal | `register generation completed` | `outcome: &'static str`, `output_count: u64` when completed; refused only: `refusal_kind: &'static str`; failed only: `error_kind: &'static str`, fixed `phase: &'static str` when useful |
| Each located label check or source-validation defect | `labels::check`, `labels::repository` | ERROR if it fails the command, WARN if nonfatal | `label check failed`, `label check warning`, or `label source validation failed` | `diagnostic_code: &'static str` from `LabelErrorCode`, `path: &str` repository-relative, `line: u64`, `column: u64` when known, `detail: &str` |
| Each plan-tree defect or nonfatal warning | `labels::plans` | ERROR if it fails the command, WARN if nonfatal | `plan check failed` or `plan check warning` | `diagnostic_code: &'static str` (`plan_failure`, `plan_warning` or `soft_target_exceeded`), `detail: &str`; no invented location from a string-only finding |
| Each unclaimed hash-citation value | `labels::hashcite` | ERROR | `hash citation unclaimed` | `diagnostic_code: &'static str`, `path: &str`, `line: u64`, `column: u64`, `shape: &'static str`, `detail: &str`; no found value |
| Each forbidden-text match | `labels::forbidden` | ERROR | `forbidden text found` | `diagnostic_code: &'static str`, `path: &str`, `line: u64`, `policy: &'static str`, `detail: &str`; no matched token |
| Each census mismatch | `labels::census` | ERROR | `census mismatch` | `diagnostic_code: &'static str`, `path: &str`, `detail: &str` with the remedy, `mode: &str` for a disallowed mode; `line` and `column` only if known |

Located checker defects are the narrow exception to the general no-path and no-free-text field rule: their repository-relative location and rendered `detail` make the failure actionable, and one defect that fails the command yields one ERROR event. Plan findings currently retain only rendered strings, so the binary emits stable broad codes and the existing actionable `detail`; it does not guess coordinates by parsing prose, and a later typed plan-diagnostic API would be needed for location fields. Binary-local Git spawn or nonzero-exit failures no longer emit their own ERROR: the scan's single `failed` completion carries a static `error_kind` and `child_exit_code` only when one exists, followed by the shared runner's one ERROR. Per-register path events, idle rule IDs, per-kind label totals, plan byte totals and the hash value are omitted because the reports or caller-owned assets already carry them.

## Naming · `sec:tracing-labels:naming`

Use literal `labels::<domain>` targets for library and binary-local work, never a binary crate name or `::command` role suffix; `cli_common::command`, `cli_common::control` and `cli_common::publication` are shared targets. Span names are lower_snake_case operations, event messages are fixed short lowercase English phrases, and field keys are lower_snake_case. Categorical fields (`outcome`, `refusal_kind`, `error_kind`, `diagnostic_code`, `phase`, `register_kind`, `shape`, `policy`) are closed static strings; `refusal_kind` appears exactly on typed refusal and `error_kind` exactly on operational failure, using an existing stable `name()` or `as_str()` verbatim where available and otherwise splitting variant names before every capital, including a single-letter word. Counts end in `_count: u64`, bytes in `_bytes: u64`, configured limits in `_limit: u64`, and a child exit is `child_exit_code: i32` only when the child exited; conversion of collection lengths saturates with `u64::try_from(n).unwrap_or(u64::MAX)` so telemetry cannot fail the operation. Results retain their existing typed schema, and no span records an outcome or completed count.

No event contains a found hash value or forbidden token, a raw Git stdout or stderr line, an argument-derived path, argv, a full report, a register's bytes, or a free-form library error. Only the located checker events above carry repository-relative `path`, optional coordinates and public-tree `detail`. Labels has no compact/live/state `family` dimension, architecture `operation_code`, evidence `standing`, progress milestone, configured time bound or measured-duration field.

## Cost · `sec:tracing-labels:cost`

File scans, register rendering, hash adjudication and report serialization are required domain work and run regardless of subscriber state. Entry spans read cheap collection lengths; completion events read existing report and diagnostic lengths, with no parallel telemetry counter. Do not join idle rule IDs, render extra paths, format errors, traverse registries, clone graphs, hash bytes or read a file solely for instrumentation. Any optional derived field must be inside `tracing::enabled!` for its literal target and level or lazily formatted; disabled tracing then pays only its callsite check. A boundary may reuse its entry enablement decision for the completion event, so scoped capture cannot record the span and miss the event through a separate cached callsite check. The shared subscriber measures `busy_ns` and `idle_ns` at span close, so labels introduces no `Instant` or elapsed-time field.

## Testing · `sec:tracing-labels:testing`

Use a package-local capture subscriber under `tracing::subscriber::with_default` for an accepted tree (`outcome = completed`, `valid = true`) and a subject one coordinate away with a located defect (`outcome = completed`, `valid = false` at INFO); the library must emit no WARN or ERROR for that expected negative, while the binary emits its V21-style located ERROR and its runner's terminal failure. `check_repository`, `harvest_sources` and `verify_census` return defects as data and `check_plans` returns a complete negative plan report, so these operations have no typed refusal event; a generator validation error supplies the DEBUG `refused` case. Assert fixed targets, names, levels, field types, report values and unchanged register bytes with and without capture; do not assert a numeric duration or ordering across threads. Every scoped capture test re-executes itself as the sole selected test in a fresh child process; the parent requires a successful exit and exactly one passing test, while the child's assertions remain strict. The capture helper in that child holds one process-wide install mutex for the whole capture and rebuilds tracing's interest cache inside `with_default` before running the subject; a regression first touches a traced call without capture, then captures it on two threads and requires exactly one span per thread. If a future labels operation spawns a thread, carry the `tracing::Dispatch` and parent span explicitly into it; a thread-local default does not propagate automatically. A small local helper may capture the fields, but no global test subscriber or new shared test-helper crate is needed.

Keep real-binary subprocess tests for each checker's direct and build modes and each generator's empty stdout and explicit assets. Assert one JSON result object plus newline or empty stdout, build-mode report/stamp behavior, TTY refusal, no raw argument-supplied Git stderr, the located `diagnostic_code`/`detail` shape, and control records for help, usage and TTY even with `RUST_LOG=off`; a dedicated child test process installs the same bootstrap and deliberately panics to assert its control record without adding a panic route to a shipped binary. An enabled INFO span yields one JSON close record with numeric `busy_ns` and `idle_ns`. A permission-dependent test fails with an explanatory panic if its environment cannot enforce the permission unless `TRIPOD_ALLOW_PRIVILEGED_SKIP` opts into an alternative symlink-loop fault that still exercises the same assertions; no unavailable path silently passes. The test harness itself writes no standard stream; it captures child streams and treats its own elapsed time as harness data. The global bootstrap and panic behavior are only asserted in fresh subprocesses, never in a process-global unit-test subscriber.

## Implementation plan · `sec:tracing-labels:plan`

1. Library commit: adds `check_repository`, `harvest_sources` and `verify_census` spans and one completion event for each directly called operation, using only existing result and census lengths; adds a test-local subscriber and accepted/adjacent-defect assertions. This work has no binary bootstrap dependency.
2. Library commit: adds `check_plans` and both register-generation spans and completion events, classifies typed `GenerateError` refusals versus operational failures, and relies on the shared `cli_common::publish_batch` instrumentation; report and generated bytes remain unchanged.
3. Binary commit: makes all seven `main` functions call `install_command_subscriber(COMMAND_NAME)` first under the implemented ADR-010 and `cli-common` contracts; runners reload the diagnostic filter and preserve direct JSON stdout, build report/stamp modes, generator asset paths and exit classes. Subprocess checks cover help, usage, TTY and panic with `RUST_LOG=off` and an enabled span-close record.
4. Binary commit after bootstrap: instruments the three tracked-tree scans, normalizes located label, plan, hash, forbidden-text and census defects to the table's fields, removes duplicate byte totals, idle IDs, per-register path progress and binary-local Git ERROR events, and verifies a complete negative report versus a child operational failure. Argument-derived Git stderr and argv remain omitted.
5. Binary test and gate commit: extends all seven subprocess contracts for output modes, structured stderr and one command terminal event, then runs the repository gate. `artifacts` can nest its `model_labels_json` call under its own render span without a new labels command event; labels uses neither the shared package's compatibility delegates nor direct stderr writes.

## Open questions for the other packages · `sec:tracing-labels:questions`

- Target naming is settled as literal `labels::<domain>` and `cli_common::<domain>` module targets with unprefixed snake_case span names; no binary-name target or extra command wrapper is needed.
- One bounded outer completion at INFO and its close record expose useful timing without flooding stderr; a complete negative check remains `outcome = completed`, `valid = false`, while expected typed library refusal is DEBUG.
- The shared `cli-common` bootstrap owns all early control records and their unchanged ADR-010 wire shape, including `RUST_LOG=off` and panic safety; all seven labels binaries install it first, while library instrumentation remains independent of process bootstrap.
- Located checker failures keep a stable `diagnostic_code`, repository-relative `path`, known line and column and rendered `detail`; non-located library events omit paths, raw child output and free-form text.
