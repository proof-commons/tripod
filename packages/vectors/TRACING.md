# Tracing design for `tripod-vectors`

## Purpose and shape · `sec:tracing-vectors:purpose`

`vectors` is a library of canonical compact ASH, live transfer, and maturity announcement evidence. It builds semantic fixtures and linked bundles, derives relation-indexed plans, materializes target transaction subjects, compares accepted controls with one-coordinate mutants, admits archived run-of-record observations, and validates and renders typed safety, continuity, recovery, history, minimality, and resource reports. It does not own target execution; its only executable is the public observation helper built from the harness-free test source.

The crate root exports the compact path (`fixture`, `bundle`, `plan`, `matrix`, `materialize`, `mutation`, `comparison`, `report`), the live path (`live_*`), and the maturity path (`maturity_*`); `error.rs` keeps construction and evidence refusals typed by producing layer. Integration tests and ignored native-run tests drive the conformance executor and write archival captures under `fixtures/`. The harness-free `tests/maturity_observer.rs` is a first-party program consumed by `scripts/elements-observer-capture.py`. Workspace callers include the reference and protocol tests in `target-elements-conformance`; its library executor and oracle run beneath the vector ceremony span.

`tracing` is an unconditional dependency under (`[ADR026-dec:tracing:core]`). Spans and completion events cover the selected materialization, validation, archive, report and native ceremony boundaries. Typed return values, report strings and archived evidence remain domain data; instrumentation observes their preparation and validation without becoming evidence or changing the accepted/refused boundary.

## Standard output and standard error · `sec:tracing-vectors:streams`

The library returns typed values or rendered bytes and never owns a standard stream. Ordinary `#[test]` stream sites are removed: deterministic measurements and census values are asserted, and redundant `RUN-REPORT` prose and elapsed-wall prints are dropped in favor of the existing archived capture files and harness timing. The required `*.timing` sidecars remain explicit result files with their existing schema; their measured values are never tracing fields. The ignored `maturity_native` producer keeps its `OBSERVER-MANIFEST` stdout record because `scripts/elements-observer-capture.py` extracts that explicit result from the producer stream; moving this protocol to a file requires a change to that script outside this package. A hand-run native test may use a scoped JSON subscriber to show bounded progress events on stderr, with no global subscriber and no direct stderr write by test code.

The harness-free `maturity_observer` is a first-party executable for the output contract. Its first statement installs `cli_common::install_command_subscriber("maturity-observer-cli")`, then it uses `run_stdout_json_command` through a normal dependency and returns `ExitCode`; the named `maturity-observer-cli` binary has its own source file that includes the pinned observer command source, so integration tests can locate it through Cargo's binary path without listing one file as two build targets. Terminal or empty stdin remains a no-op with empty stdout and exit 0; a valid observation publishes one JSON object plus newline; a failure emits one JSON diagnostic through the shared runner and exits 1, without Rust's plain-text `Result` termination line. The runner's stdout TTY refusal remains a control record and exit 2. A multi-record process result, if later needed, must be documented NDJSON. Full reports and captures remain explicit files.

Every standard-error byte of a first-party program comes from the one tracing subscriber shared by `cli-common`: its unfiltered control route handles help, usage, TTY refusal and panic, and its filtered diagnostic route handles normal events and span close records through the same locked writer. The control route preserves the record bytes and never falls back to a direct writer; its panic dispatch uses a nonblocking lock and drops a reentrant record. Diagnostic JSON retains `timestamp`, `level`, `target`, `fields`, `span` and `spans`, while control JSON retains its ADR-010 `schema` and `kind`. The observer executable installs the subscriber and panic hook as its first action; the runner reloads the diagnostic filter from nonempty `RUST_LOG`, then its debug setting, then its command default, while control records remain visible even with `RUST_LOG=off`. An invalid `RUST_LOG` falls back to `info` with a value-free WARN `filter directive rejected` event. An INFO `cli_common::command` `command` span encloses the observer runner and result publication; it ends in one INFO `command completed` event on success or one ERROR `command failed` event on failure, while TTY refusal has only its control record. The library and ordinary tests never install a global subscriber. ADR-010 includes harness-free first-party programs and requires the subscriber to produce their stderr records, including early control records (`[ADR010-rule:output:streams]`), (`[ADR010-rule:output:early-startup]`), (`[ADR010-rule:output:implementation]`).

## Spans · `sec:tracing-vectors:spans`

| Operation | Target and span name | Level | Fields (type) | Duration worth measuring |
|---|---|---|---|---|
| Test oracle `keyed_stack_core::evaluate` | `vectors::keyed_stack_model`, `evaluate_keyed_model` | DEBUG | `script_bytes: usize` | Test-only traced entry; target retains the historical model name. The library reader calls untraced core entries, with no member-loop span. |
| `keyed_history_reader::read` | `vectors::keyed_history_reader`, `read_keyed_history` | INFO | `event_count: usize`, `key_count: usize` | One finite byte/evidence derivation; no production chain acceptance. |
| Compact `materialize::materialize` and `materialize_sponsored` | `vectors::materialize`, `materialize_subject` | DEBUG | `family: &'static str` (`compact`), `sponsored: bool` | Per-case transaction assembly, serialization and independent checks can be substantial. |
| `first_party::validate_first_party_negative` | `vectors::validation`, `validate_mutant` | DEBUG | `family: &'static str` (`compact`), `boundary: &'static str` (`compiler_required_dependency`) | The validator runs both the published control and its one-field mutant. |
| `maturity_corpus::admit_maturity_corpus` | `vectors::corpus`, `admit_run_of_record` | INFO | `family: &'static str` (`state`), `archive_kind: &'static str` (`maturity`) | Digest, grammar and replay checks dominate archive admission. |
| `report::validate_bound_run`, reached by `validate_operation_report` | `vectors::report`, `validate_evidence_report` | INFO | `family: &'static str` (`compact`), `report_kind: &'static str` (`operation`), `row_count: u64` | The binding and transcript comparison checks every submitted case. |
| shared maturity native-test `execute` wrapper | `vectors::native_test`, `execute_ceremony` | INFO | `family: &'static str` (`state`), `ceremony_id: &'static str` (`maturity_native`) | The parent ceremony includes the in-process conformance executor call; its `executor_run` child separates execution time. |

Use child spans for measured phases only where the parent duration hides a concrete decision, such as archive parse versus cross-link validation. A JSON close record for each enabled span reports `busy_ns: u64` and `idle_ns: u64` by default; no open or enter record is needed, and nested inclusive durations are not summed. No event carries a measured duration or correlation ID. Do not span per byte, witness item, or loop iteration, and do not put a `case_id` on a span.

The fixed canonical bundle and evidence-plan constructors have typed error returns, but their public inputs cannot produce a controlled one-coordinate refusal: canonical bundle parameters are constant, and the plan consumes a validated fixture with no mutable census. They remain uninstrumented until a real caller-supplied boundary offers a control and adjacent refused subject; their work is still included in an enclosing caller span when one exists.

## Events · `sec:tracing-vectors:events`

| Operation or milestone | Target | Level | Fixed message | Fields (types) |
|---|---|---|---|---|
| Test-oracle byte model completion | `vectors::keyed_stack_model` | DEBUG | `keyed model evaluated` | `outcome: &str`, `model_only: bool`, `primitive_count: u64` on success, `refusal_kind: &str` on refusal |
| Keyed history reader completion | `vectors::keyed_history_reader` | INFO | `keyed history read completed` | `handle_count: usize`, `incomplete_count: usize`, `relation_count: usize`; one event per returned reading, including incomplete readings |
| Keyed history reader refusal | `vectors::keyed_history_reader` | DEBUG | `keyed history read refused` | `refusal_kind: &str`, `boundary: Boundary` (debug); one event per refusal |
| Subject materialization completion | `vectors::materialize` | DEBUG, including refusal and failure | `subject materialized` | `family: &'static str`, `sponsored: bool`, `outcome: &'static str`, `refusal_kind` or `error_kind` on its respective outcome |
| Control or mutant validation completion | `vectors::validation` | DEBUG, including refusal and failure | `mutant validated` | `family: &'static str`, `boundary: &'static str`, `outcome: &'static str`; when a subject was observed, `standing: &'static str` and `observed_refusal_kind: &'static str` if its standing is `refused`; `refusal_kind` or `error_kind` only for this operation's own refusal or failure |
| Archive admission completion | `vectors::corpus` | INFO when completed or failed; DEBUG when refused | `run of record admitted` | `family: &'static str`, `archive_kind: &'static str`, `outcome: &'static str`, `row_count: u64` when returned; `refusal_kind` or `error_kind` on its respective outcome; no `standing` |
| Evidence report validation completion | `vectors::report` | INFO when completed or failed; DEBUG when refused | `evidence report validated` | `family: &'static str`, `report_kind: &'static str`, `outcome: &'static str`, `completed_count: u64` when returned; `refusal_kind` or `error_kind` on its respective outcome; no `standing` |
| Native ceremony completion | `vectors::native_test` | INFO when completed or failed; DEBUG when refused | `ceremony completed` | `family: &'static str`, `outcome: &'static str`, `accepted_count: u64`, `refused_count: u64`, `unobserved_count: u64` when returned; `refusal_kind` or `error_kind` on its respective outcome |
| Hand-run closure observation | `vectors::native_test` | INFO | `closure observation` | `case: &str` from a static case registry, `layer: &'static str`; child detail stays in the asserted response and never enters tracing |

The conformance executor exposes no progress callback to this wrapper, so replaying captured operations as if they were live milestones would misstate progress. The ceremony emits its bounded count snapshot only at completion; counts are obtained from the already held capture and no traversal runs when tracing is disabled. The capture count becomes known only after execution, so it is an event field rather than a span-entry field.

Each instrumented public operation emits exactly one completion event inside its span when it returns, with its outcome and available summary counts; same-crate public wrappers call an uninstrumented internal core to avoid duplicate events, while calls into other crates retain their own events. `outcome = "completed"` means a typed result returned even if that result reports a refused test subject or an incomplete observation; `outcome = "refused"` means the operation returned an expected typed refusal, and `outcome = "failed"` means operational failure. An exhausted policy budget is a typed refusal at DEBUG. A failed library completion uses its span's tier; the command boundary owns the one ERROR diagnostic. WARN is reserved for a recoverable anomaly after which the result remains usable. Counts are snapshots from typed plan/report values, never parallel telemetry counters; frequent value helpers emit no success event, and per-row detail is omitted unless a TRACE consumer exists.

## Naming · `sec:tracing-vectors:naming`

Every target is an explicit literal `vectors::<domain>` with domains `bundle`, `plan`, `materialize`, `validation`, `corpus`, `report`, and `native_test`; binary-local observer work uses its owning domain, never the binary crate name or `::command`. Span names are unprefixed lower_snake_case operations, and event messages are fixed lowercase English phrases rather than interpolated values. Field keys are lower_snake_case. The shared categorical values here are `outcome: &'static str` in `completed`, `refused`, `failed`; `family: &'static str` in `compact`, `live`, `state`; and `standing: &'static str` in `accepted`, `refused`, `unobserved`, only for observations of test subjects. `boundary`, `archive_kind`, `report_kind`, `ceremony_id` and `step_id` are static values from their existing typed or public registries, never caller-provided strings; a typed variant's stable payload-free name supplies `refusal_kind` only on an operation refusal, `observed_refusal_kind` only on a refused observed subject, and `error_kind` only on an operational failure. `phase` may be `validate`, `stage`, `publish`, `execute` or `serialize` when the failing step matters; no field repeats the span's operation name.

Where one architecture operation is involved, its identity is `operation_code: u16` from `OperationId::code()`, never a generic `operation` string. Cardinalities use a meaningful `<noun>_count: u64`, converted at emission with saturation, and byte quantities use `<subject>_bytes: u64`; limits use `<noun>_limit: u64` or `<subject>_byte_limit: u64`. A configured time bound may be `<noun>_ms: u64`, but measured durations appear only in span close records or archival result files. Progress uses `completed_count: u64` and `total_count: u64` at bounded milestones, never one event per fast item. `command`, `output_mode`, `exit_class` and `result_published` belong to `cli-common`, and the command span supplies them as parent context rather than duplicating them in vector events. No event records amounts, nonces, hash or token values, transaction sizes or weights, report contents, scripts, witnesses, keys, argv, caller-supplied paths, child stream data, free-form error text or Rust type paths; an artifact is named only by a static role (`[ADR010-rule:output:data-classification]`).

## Cost · `sec:tracing-vectors:cost`

Bundle IDs, serialized transactions, report renderings and error formatting can be expensive and may expose more than the event needs. Use already held primitive counts, booleans and static variant names; do not calculate hex digests, traverse a census, clone an evidence object or render a report solely for tracing. Compute a derived DEBUG field only behind `tracing::enabled!` or through lazy formatting. Span entry encloses the measured work, while the subscriber measures its duration and emits one close record; instrumentation holds no extra `Instant` and allocates nothing without an enabled subscriber. Archival timing uses the existing result-side measurement path because a sidecar is a result artifact, not a tracing record.

## Testing · `sec:tracing-vectors:testing`

Unit tests assert typed returns, the refusal boundary, census and serialized bytes independently of tracing. A small package-local subscriber using `tracing::subscriber::with_default` captures events and span close records in memory for one control and a mutant one coordinate away; assert the literal target, level, span name, fixed message, `outcome = "completed"`, `standing = "refused"` with `observed_refusal_kind`, and no WARN or ERROR for the expected negative. Compare the same returned values and bytes with no subscriber. If a test spawns a thread, explicitly carry its dispatcher and enter the parent span in that thread. Do not assert wall durations or ordering across threads, and do not add a shared test-helper crate.

Each scoped capture test re-executes itself as the only selected test in a fresh child process, using its exact module-qualified test path and a child marker; the parent requires successful exit and a one-passed libtest summary, showing captured child output on failure. This isolates its process-wide tracing callsite interest from uncaptured tests running concurrently in the parent suite. Inside the child, the capture helper holds a static install mutex for the whole capture and rebuilds the callsite interest cache after installing its scoped subscriber and before running the subject.

Subprocess tests of `maturity_observer` capture streams separately: terminal or empty stdin yields no stdout and exit 0, valid input yields one JSON object plus newline, a failure yields JSON stderr and exit 1 with no stdout or plain-text `Error:` line, and terminal stdout is refused by the shared control route even with `RUST_LOG=off`. The shared control route also keeps help, usage and panic records visible for programs that have those paths; enabled INFO spans yield numeric close-record fields. Ordinary test cases write no stream; their deterministic values are assertions and required archival reports or timing samples are explicit files. A manually run ignored native test may use a scoped subscriber to render bounded progress events as stderr JSON.

The shared maturity native ceremony wrapper is asserted with a synthetic byte-producing control and an adjacent typed plan refusal, so the span, terminal level and byte invariance are tested without starting a node; the ignored native cases exercise the same wrapper around the actual conformance executor.

## Implementation plan · `sec:tracing-vectors:implementation`

1. The first library commit instrumented compact and sponsored materialization with one completion event each and tested returned bytes and a one-coordinate funding or authorization refusal with and without scoped capture; the fixed canonical bundle and plan remain uninstrumented for the reason in “Spans”.
2. The second library commit instrumented first-party negative validation, maturity corpus admission and compact operation-report validation with `standing` only on observed subjects, `refusal_kind` for operation refusal and `error_kind` for operational failure; scoped capture tests cover completed controls and adjacent refusals.
3. The native-test commit added `vectors::native_test` `execute_ceremony` around the shared maturity executor call with an aggregate completion event and a synthetic scoped control/refusal test; the conformance executor's `executor_run` is its child through parentage. The executor exposes no live progress callback or known entry `case_count`, so the wrapper emits no artificial progress milestone.
4. With the shared subscriber, runner and ADR-010 contract in place, the observer commit migrated the harness-free `maturity_observer` to `install_command_subscriber` and `run_stdout_json_command` through a normal dependency; a separate named binary source includes the pinned command source for reliable subprocess tests. Empty or terminal stdin behavior is preserved, and subprocess tests assert stdout, failure, TTY refusal and `RUST_LOG=off` control records. The runner receives the already rendered observation parsed as a JSON value, and the subprocess test requires its serialized stdout bytes to equal the former rendering plus one newline.
5. The test-output commit removed ordinary test stream writes and Rust plain-text diagnostic termination: deterministic values became assertions, redundant prose and elapsed-wall prints were dropped, required `*.timing` sidecars stayed in explicit files, and a closure observation became a tracing event. The ignored native producer keeps its explicit `OBSERVER-MANIFEST` stdout protocol for the capture script named in “Standard output and standard error”.
6. The assembled series passed the package implementation gate. The shared compatibility delegates remain available for other binaries that still use them; their retirement and the workspace's direct-stderr lint rule are outside this package.

## Open questions for the other packages · `sec:tracing-vectors:questions`

- The native ceremony is the parent of the conformance executor's `executor_run`; `ceremony_id` is a static public registry label on the vector span, and parentage supplies cross-crate correlation without raw request or case identifiers.
- `standing` is limited to observed test subjects and has `accepted`, `refused`, `unobserved`; operation outcomes are `completed`, `refused`, `failed`, with `refusal_kind` reserved for the operation's own typed refusal and `observed_refusal_kind` for the subject's refusal. Counts use meaningful `_count: u64` names with saturating conversion.
- Ordinary tests write no standard stream; required native run records go to explicit files, the ignored native producer retains its capture-script manifest protocol, and the harness-free observer publishes one JSON stdout result through the installed shared `cli-common` subscriber and runner.
- Archived `*.timing` sidecars keep their existing result schema and measurement path; operational duration is the subscriber's span close record and is never copied into a tracing event.
