# `cli-common` tracing engineering design

## Purpose and shape · `sec:tracing-cli-common:purpose`

`cli-common` is the shared command-line boundary for ADR-010: it parses clap control exits, owns JSON result and control-plane records, configures stderr tracing, handles panics and TTY refusal, maps command outcomes to exit classes, and publishes checker reports and stamps. It is a library with no binary; each consuming binary calls its entrypoint helpers.

`src/lib.rs` exports the stream, runner, redaction, output-role and stamp APIs; private `src/publication.rs` implements compare, stage and publish for asset batches, with its public types re-exported at the root. `src/tests/mod.rs` and `tests/public_api.rs` test those contracts. Binaries in `artifacts`, `document-stamps`, `execwrap`, `flatten-latex-main`, `labels` and `target-elements-conformance` use the shared command setup; `artifacts` and `labels` also call `publish_batch`.

ADR-026 supplies the unconditional `tracing` dependency and assigns timings to spans and counts and outcomes to events (`[ADR026-dec:tracing:core]`). ADR-010 already separates structured stdout results from JSON stderr control and diagnostics (`[ADR010-rule:output:streams]`), but current early control records bypass its late-installed subscriber and `execwrap` may relay raw child bytes to both streams. The implementation changes ADR-010 so one subscriber produces all first-party stderr and raw child streams go only to explicit file routes; result JSON, control-record schema, exit classes and redaction remain stable.

## Standard output and standard error · `sec:tracing-cli-common:streams`

Successful single-result commands keep one JSON object and a trailing newline on stdout through `emit`; checker direct mode uses the same form, checker build mode writes an explicit report and stamp with empty stdout, and side-effect commands leave stdout empty. Failure before publication leaves stdout empty, while a failed write after publication begins may leave a partial prefix. The ADR-010 amendment withdraws the child-byte relay exception for both streams: `execwrap` must route each child stream to an explicit file and refuse an unrouted stream before spawning with a usage control record and exit 2; child statuses 3-255 retain their relay meaning (`[ADR010-rule:output:json]`), (`[ADR010-rule:output:exit-codes]`).

Every first-party binary's first statement becomes `cli_common::install_command_subscriber(command_name)`, which installs its one global subscriber and JSON panic hook together before clap or other panic-capable work. The subscriber has an always-enabled `cli_common::control` route and a filtered diagnostic route, both using the same non-interleaving locked stderr writer. Libraries never install a subscriber, and unit tests never replace a process-global one. The rule also covers harness-free programs run by scripts and first-party mock executables: their declared protocol stdout may intentionally contain malformed test frames, but their own stderr is subscriber-produced JSON; ordinary test cases inside a harness remain outside the executable stream contract.

Before parsing, nonempty `RUST_LOG` selects the diagnostic filter, otherwise `info` does; no per-command default is needed before parsing. After parsing, a runner reloads the diagnostic filter from a process-global handle using nonempty `RUST_LOG`, then parsed `--debug`, then the command default, including `execwrap`'s `--quiet` WARN default. An unparseable directive falls back to `info` and emits one WARN `filter directive rejected` event without echoing the environment value. The control route ignores all diagnostic filters, including `RUST_LOG=off`, so help, version, usage, TTY refusal and panic records remain observable (`[ADR010-rule:output:diagnostics]`), (`[ADR010-rule:output:early-startup]`).

`emit_control_plane_record` dispatches a tracing event to the control route instead of writing directly; its formatter reproduces the existing `ControlPlaneRecord` JSON bytes (`schema`, `command`, `kind`, `message`, optional `fields`) and one newline. Its `io::Result` reports serialization errors only, because subscriber write errors cannot be returned through an event; with no subscriber the record is dropped, never written through a fallback. `ControlPlaneRecord::status` and `::diagnostic` remain schema builders without current binary callers; ordinary runtime diagnostics use the filtered tracing route. Help, version and status are INFO; usage and TTY refusal are WARN; panic and control diagnostic are ERROR. The panic hook emits at most one best-effort record, uses a nonblocking lock and drops it on contention or re-entry, then exits 1; its payload remains hidden until parsed `--debug` enables it (`[ADR010-rule:output:control-plane]`), (`[ADR010-rule:output:panics]`).

Until every binary moves to `install_command_subscriber`, the `install_json_panic_hook` delegate preserves its existing quiet clean-run stderr: when neither nonempty `RUST_LOG` nor `--debug` selects a filter, runner reload adds `cli_common::command=warn` to the caller default. This hides its INFO command completion and close records from the legacy binary's subscriber without changing their level or the events seen by a scoped capture subscriber; explicit bootstrap uses the normal default, and an explicit filter or debug flag still reveals the records. This compatibility rule ends with removal of the startup delegates in commit 6.

Diagnostic events and span closes retain the `tracing-subscriber` JSON envelope with `timestamp`, `level`, `target`, `fields` containing `message`, and current `span` and `spans`; control records retain their distinct ADR-010 schema. The shared writer is the only first-party stderr sink. `install_json_panic_hook` and the `init_json_tracing*` APIs remain temporary delegates to bootstrap and reload while binaries migrate, then are removed after all binary changes are imported; runners themselves install nothing. The implementation's first commit amends ADR-010's streams, early-startup, control-plane, diagnostics, panic, implementation and verification clauses before code changes, and its import is atomic with those changes. The orchestrator owns the later `clippy.toml` rule denying direct `std::io::stderr()` outside the shared implementation; ADR-026 needs no amendment.

## Spans · `sec:tracing-cli-common:spans`

| Operation | Span name, explicit target, level | Entry fields and duration reason |
|---|---|---|
| Execute a command and publish its result | `command`, `cli_common::command`, INFO | `command: &str` (a fixed binary name at entry), `output_mode: &'static str` (`stdout`, `asset`, `none`); measures semantic work and any result/report/stamp publication, with a TTY refusal checked before execution. The async runner instruments its future rather than holding a guard across `.await`; custom mains use the same parent span. |
| Validate, stage and publish an asset batch | `publish_batch`, `cli_common::publication`, INFO | `asset_count: u64`; measures compare, staging, sync, rename and any partial-publication window once for callers in `artifacts` or `labels`. |
| Stage one changed asset | `stage_asset`, `cli_common::publication`, DEBUG | `role: &'static str`, `written_bytes: u64`; isolates write and sync cost for changed assets, with the role selected from a fixed safe vocabulary rather than an arbitrary caller string. |

There is no parse, stdout-emission or separate checker-publication span: clap has no duration consumer, and the command span already covers result writing. Spans carry entry context only; completed counts and outcomes appear in their events. Every enabled span emits one close record by default with its name, target, level, entry fields, `busy_ns: u64` and `idle_ns: u64`, and no open or enter record. Nested durations are inclusive; a collector derives exclusive time from parentage and must not sum nested durations as independent work. The subscriber's close layer uses `Instant` internally; no measured-duration event is added.

## Events · `sec:tracing-cli-common:events`

| Event and trigger | Explicit target, level, fixed message | Fields and interpretation |
|---|---|---|
| Required control record | `cli_common::control`; INFO help/version/status, WARN usage/TTY refusal, ERROR panic/diagnostic; current control `message` text | Existing `schema: u32`, `command: &str`, `kind: &str`, `message: &str`, optional typed `fields`; the unfiltered control formatter keeps the current wire record exactly. |
| Invalid diagnostic filter | `cli_common::command`, WARN, `filter directive rejected` | No directive value, raw environment text or argument; the filter becomes `info`. |
| Runner or custom main succeeds | `cli_common::command`, INFO, `command completed` | `exit_class: &'static str` (`success`), `output_mode: &'static str`, `result_published: bool`; one terminal event after the result or asset publication succeeds. |
| Runner or custom main fails operationally | `cli_common::command`, ERROR, `command failed` | `exit_class: &'static str` (`failure`), `phase: &'static str` (`execute`, `serialize`, `publish`), and centrally redacted `error: &str`; a custom main may supply fixed `error_kind: &'static str` without text instead. |
| Asset batch succeeds or fails operationally | `cli_common::publication`, INFO, `asset batch published` on completion or `asset batch failed` on failure | `outcome: &'static str` (`completed` or `failed`), `asset_count: u64`, `bytes_changed_count: u64`, `mode_changed_count: u64`, `unchanged_count: u64`; failure also has `phase: &'static str` (`stage`, `publish`), `error_kind: &'static str` and `published_count: u64` for prior completed publication steps. |
| Aliased batch destination is refused before publication | `cli_common::publication`, DEBUG, `asset batch refused` | `outcome: &'static str` (`refused`), `refusal_kind: &'static str` (`aliased_outputs`) and `asset_count: u64`; no WARN or ERROR record. |

Usage and TTY refusal produce their control record alone, with no WARN terminal event. A batch completion event is emitted once inside `publish_batch`, reading change counts from `PublicationChange`; no checker-publication event, second counter store or per-asset event is added. No batch is slow enough to justify a progress milestone. Runtime failures emitted by the command boundary are the only ordinary ERROR diagnostics in this crate; a returned library failure remains typed metadata at its span's tier, while a panic is the exceptional control ERROR.

## Naming · `sec:tracing-cli-common:naming`

Every span and event uses an explicit literal Rust crate-stem target: `cli_common::control`, `cli_common::command` or `cli_common::publication`. Span names are bare lower_snake_case operations, and event messages are fixed lowercase English phrases; machine meaning is in static lower_snake_case field keys and bounded static string values, not interpolated prose. The `command` span alone owns `command: &str` supplied as a fixed binary name and `output_mode: &'static str` (`stdout`, `asset`, `none`); terminal events own `exit_class: &'static str` (`success`, `failure`, `usage`) and `result_published: bool`. Libraries do not duplicate command fields, and no generic `operation` or correlation ID is added.

For this package `outcome` is `completed` or `failed` on batch publication, and the workspace vocabulary reserves `refused` for expected typed domain refusal; a completed report's negative verdict remains a field in that report. `refusal_kind` names a stable typed refusal exactly when an operation returns one; `error_kind` names an operational failure exactly when `outcome = failed`; `phase` names a fixed step such as `validate`, `stage`, `execute`, `serialize` or `publish`. Counts use `<noun>_count: u64`, converted from collection lengths by saturation, bytes use `<subject>_bytes: u64` such as `written_bytes`, and configured limits use `<noun>_limit: u64`. No amount, nonce, hash, raw result, child bytes, argv value, caller-supplied path, free-form library error or Rust type path becomes a tracing field (`[ADR010-rule:output:data-classification]`).

INFO marks bounded outer operations and completed batch observations, DEBUG marks the changed-asset stage, WARN marks recoverable filter rejection and usage/TTY control, and ERROR marks terminal command failure or panic. Expected library refusals are DEBUG rather than WARN or ERROR. A command span puts its name and output mode in the diagnostic JSON span list; ordinary diagnostic events do not gain a `schema` field, which belongs to control records.

## Cost · `sec:tracing-cli-common:cost`

Span fields are cheap static names, existing lengths or byte lengths; a length converted to `u64` saturates rather than risking an instrumentation panic. Batch summary counts are folded from already-produced `PublicationResult` values only when the event is enabled, while `PublicationChange` remains the source of truth. The stage role is selected from a fixed safe vocabulary rather than allocating or displaying a destination path. No traversal, clone, hash, string formatting, clock sample or JSON serialization runs solely for a disabled event; a derived field is guarded by `tracing::enabled!` or lazy formatting. Required control records intentionally serialize even with diagnostics filtered off, but a record is not serialized merely to check enablement. Terminal `error` text is formatted and centrally redacted once when its event is enabled; stdout result serialization remains necessary independent of tracing.

## Testing · `sec:tracing-cli-common:testing`

Unit instrumentation tests use `tracing::subscriber::with_default` and a package-local in-memory capture subscriber to assert explicit target, level, span name, parentage, fixed message, typed fields and one completion event without installing a global subscriber. Each capture test re-executes itself as the only selected test in a fresh process, because concurrent uncaptured unit tests can change tracing's process-wide callsite interest while a scoped capture runs; the parent still runs the suite in parallel. One process-wide mutex serializes capture installs within that process, and each capture rebuilds the tracing callsite interest cache inside `with_default` before the subject runs; a regression touches a callsite without capture, then requires one captured span on each of two test threads. A control and a one-coordinate typed refusal assert `completed` versus DEBUG `refused` where a boundary has that contract, with unchanged returned values and bytes both with and without capture. A subject that spawns a child thread explicitly carries its dispatcher with `tracing::dispatcher::get_default(Dispatch::clone)` and enters the parent span in that thread; no event order across threads or exact duration is asserted.

Process-global startup is tested only by re-executing this package's test binary with `std::env::current_exe()`, `--exact <test>` and a mode variable, giving each case a fresh subscriber and panic hook. Child-process cases assert byte-identical help, version, usage, TTY and panic control records with `RUST_LOG=off`, invalid-filter warning without the directive value, one parseable JSON diagnostic or control object per stderr line, one numeric close record per enabled INFO span, and no direct stderr fallback when bootstrap is absent. Panic cases cover an uncontended and a contended writer, payload hidden before parsed `--debug`, one best-effort record and exit 1. Writer-parametric tests retain exact single-object stdout plus newline, serialization errors and partial-write behavior; the existing `emit_to_real_stdout_succeeds` test still calls `emit` under harness capture to exercise its real stdout lock, without installing a subscriber. Subprocesses assert empty stdout on pre-publication failure and the correct exit class, and no test sets a global subscriber in the parent test process.

A child-process compatibility case starts through `install_json_panic_hook` and asserts that a successful legacy command with its default INFO level still leaves stderr empty; explicit bootstrap cases continue to assert the visible INFO completion and numeric close records.

## Implementation plan · `sec:tracing-cli-common:implementation`

1. `docs(cli-common): amend ADR-010 for subscriber-owned streams` — amend streams, early startup, control records, diagnostics, panic, child stream routing and verification before code changes; the `cli-common` implementation step is imported atomically so main never contains the amendment without its code, and ADR-026 stays unchanged.
2. `feat(cli-common): bootstrap the subscriber and control route` — install the one subscriber and hook as the first binary action, keep one locked writer, add the always-enabled byte-identical control formatter, process-global filter reload, safe fallback warning and nonblocking panic path; retain the old public initialization APIs as delegates for the binary migration, and add self re-execution tests.
3. `feat(cli-common): emit numeric span close records` — enable one close record per filtered span with numeric busy and idle nanoseconds, no open or enter records, and subprocess assertions for the JSON envelope and `RUST_LOG=off` control delivery.
4. `feat(cli-common): instrument command runners` — open the INFO command span after parsing and TTY preflight, instrument the async future, provide the same span and terminal event to custom mains, reload the diagnostic filter and panic flag in runners, and emit exactly one terminal event on success or operational failure; binary stdout bytes and exit classes remain unchanged, while the test-only direct `emit` call moves behind a writer or child-process assertion.
5. `feat(cli-common): instrument asset batch publication` — add the INFO batch span, DEBUG changed-asset stage span and one aggregate completion event with safe static roles and `PublicationChange` counts; `artifacts` and `labels` add no wrapper or per-asset publication event.
6. `refactor(cli-common): remove startup delegates after binary migration` — wait until the binary steps in `artifacts`, `document-stamps`, `flatten-latex-main`, `labels`, `target-elements-conformance` and `execwrap`, plus the harness-free `vectors` program, have been imported; then remove `install_json_panic_hook` and `init_json_tracing*`. Library instrumentation in those packages can proceed independently of the shared bootstrap; the orchestrator adds the direct-stderr `clippy.toml` rule.

## Open questions for the other packages · `sec:tracing-cli-common:questions`

- The command span starts after parsing and stdout TTY preflight; there is no parse span, and help, usage and TTY refusal have only their required control record.
- The shared names are explicit crate-stem module targets, bare operation spans, fixed English event messages, `completed`/`refused`/`failed` domain outcomes, `*_count: u64` observations and separate ADR-010 `exit_class` values; only `cli-common` owns command fields.
- Before parsing the diagnostic filter uses nonempty `RUST_LOG` or `info`; after parsing runners reload it from the process-global handle using `RUST_LOG`, parsed `--debug` and the command default, so async entrypoints hold no handle.
- Progress uses bounded milestones only when units are slow enough for an operator to wait; this package adds no batch-progress event, and span close records provide ordinary timing.
- The `cli-common` implementation starts with the ADR-010 amendment and subscriber change; other libraries do not wait for that import, while binaries do, and the separate orchestrator change denies direct stderr use outside the shared implementation.
