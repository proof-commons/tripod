# Model tracing engineering design

## Purpose and shape · `sec:tracing-model:purpose`

`tripod-model` is the transparent executable reference state machine for the attestation contract. `genesis` constructs a `World`; sealed operation requests and `transition::execute` apply protocol transitions and check the resulting global invariant. `Transition::apply` remains a public lower-level path with a valid-world precondition, and `World` remains mutable for fault fixtures. The crate is a library without a binary or command-line entry point.

State and rules live in `world`, `pool`, `asset`, `scalar`, `constants`, `policy`, `shape`, `recognition`, `queries`, and `ops`; execution and proof surfaces live in `kernel`, `transition`, `invariant`, `history`, `certify`, and `genesis`; evidence adapters live in `conformance`, `ledger`, `audit`, `quiescence`, `maintenance`, `property`, `manifest`, and `artifacts`. Unit, property, and corruption fixtures are in `src/tests`, while `tests/public_api.rs` checks the external boundary. Fallible APIs return `Guard`, `InvariantError`, `ExecutionBindingError`, `ConformanceProjectionError`, or ledger codec, query, and differential errors.

`architecture` supplies the typed manifest and numeric `OperationId::code()` values; `realization` supplies target-independent semantic relations that model conformance adapters observe but do not use to decide model acceptance. `artifacts` calls `model::artifacts::declassification_json()` to obtain returned publication bytes. No model API directly owns a process stream or subscriber.

## Standard output and standard error · `sec:tracing-model:streams`

The model library writes neither stream. `World`, `QuiescenceOutcome`, query bytes, indexer snapshots, conformance observations, and errors remain typed returns; a first-party command that publishes one uses `cli-common` to write one JSON object and newline or documented NDJSON on stdout, or an explicit asset path. A result command refuses terminal stdout, leaves stdout empty on failure before publication, and follows ADR-010's partial-write and exit-class rules (`[ADR010-rule:output:streams]`, `[ADR010-rule:output:json]`). Model events never become result records.

The model has no direct stderr writes; its events reach stderr only through the calling executable's JSON tracing subscriber. The library installs no subscriber or panic hook and never writes a control record. A future model-facing binary first calls `cli_common::install_command_subscriber(command_name)`, which installs the one process subscriber and panic hook before parsing; after parsing its runner reloads the diagnostic filter with nonempty `RUST_LOG`, then `--debug`, then the command default. The reload handle stays inside `cli-common`, so the model holds none. The unfiltered control route preserves help, version, usage, TTY-refusal, and panic records and shares a locked writer with the filtered diagnostic route; even `RUST_LOG=off` cannot hide required control records. An invalid `RUST_LOG` falls back to `info` with a fixed warning that does not echo the directive.

ADR-010 requires every first-party stderr byte to come from the shared `cli-common` subscriber, including early control records; it preserves the control-record JSON schema, redaction, panic safety, filter precedence, and exit classes, and requires `execwrap` child bytes to use explicit file routes on both streams. The model has no child stream or executable. The subscriber's diagnostic JSON includes the active span list and, for each enabled span, one close record containing `busy_ns: u64` and `idle_ns: u64`; the model adds no measured-duration event. `cli-common` owns the INFO command span and the one terminal command record, so library refusals never become a second user-facing command error (`[ADR010-rule:output:diagnostics]`, `[ADR026-dec:tracing:core]`).

Public wrappers use uninstrumented internal cores when one public model API calls another and an extra same-crate completion would duplicate the call. A driver intentionally executing successive protocol transitions retains the `execute` completion for each transition; driver-level per-action events are omitted. Nested durations are inclusive and must not be summed as independent wall time.

## Events · `sec:tracing-model:events`

An instrumented public operation emits one completion event inside its span on return. `outcome` is exactly `completed` for a returned typed result, `refused` for an expected typed refusal, or `failed` for an operational or internal failure; a refusal has `refusal_kind` and a failure has `error_kind`. A completed conformance report can still have a negative semantic verdict, which remains returned data and is not recoded as a refusal. The span tier supplies the completion level, except that every expected refusal is DEBUG.

| Boundary | Target | Level and fixed message | Fields (name: type) |
|---|---|---|---|
| `genesis` | `model::genesis` | INFO completed or failed, DEBUG refused; `model genesis completed` | `outcome: &'static str`, `refusal_kind: &'static str` on ordinary refusal from `Guard::name()`, `error_kind: &'static str = "invariant_failure"` if its postcondition broke. |
| `execute` | `model::transition` | DEBUG; `model transition completed` | `outcome: &'static str`, `operation_code: u16` or static `request_kind: &'static str`, `history_count: u64` on completion, `refusal_kind: &'static str` from `Guard::name()` on ordinary refusal, `error_kind: &'static str = "invariant_failure"` when its invariant postcondition broke. |
| Direct `check_invariant` | `model::invariant` | DEBUG completion; `model invariant checked` | `outcome: &'static str`, `utxo_count: u64`, `history_count: u64`, `error_kind: &'static str` on a broken invariant. |
| Invariant break detected by genesis, execution, or a maintenance driver and collapsed into `Guard::InvariantFailure` | `model::invariant` | ERROR once; `model invariant failed` | `error_kind: &'static str` from `InvariantError::name()`; direct `check_invariant` returns the precise error and emits only its DEBUG `failed` completion. |
| `bind_execution` | `model::transition` | DEBUG; `model binding completed` | `outcome: &'static str`, `refusal_kind: &'static str` on refusal from a static `ExecutionBindingError` variant helper. |
| Public `observe_announce_maturity`, `observe_compact_ash`, and `observe_live_transfer` | `model::conformance` | DEBUG; `model projection completed` | `outcome: &'static str`, `branch: &'static str`, `refusal_kind: &'static str` on refusal from a static `ConformanceProjectionError` variant helper. |
| `compare_attestation_indexers` | `model::ledger` | DEBUG; `model index comparison completed` | `outcome: &'static str`, `event_count: u64` and `address_count: u64` on completion, `refusal_kind: &'static str` on typed mismatch, `error_kind: &'static str` if comparison cannot run. |
| Public maintenance driver | `model::maintenance` | INFO completed or failed, DEBUG refused; `model maintenance finished` | `outcome: &'static str`, `driver: &'static str`, `step_count: u64`, `refusal_kind: &'static str` on ordinary refusal, including `Guard::ZeroProgress.name()` for no progress, `error_kind: &'static str = "invariant_failure"` if its postcondition broke. |
| Public property trace driver | `model::property` | DEBUG; `model property trace completed` | `outcome: &'static str = "completed"`, `applied_count: u64`, `rejected_count: u64`, `step_count: u64`. |

There is no second ERROR in `execute` for an invariant break, no `model maintenance stalled` event, and no per-action maintenance or property event. Expected guard refusals, including one-coordinate negative subjects and zero progress, are DEBUG even when an outer driver span is INFO. A failed library operation returned to a caller stays at its span tier; only an invariant break collapsed into `Guard::InvariantFailure` by genesis, execution, or maintenance gets the exceptional library ERROR. A binary that treats a returned refusal as fatal emits its own single terminal ERROR through `cli-common`.

## Naming · `sec:tracing-model:naming`

Targets are literal `model::<owning_module>` strings, span names are unprefixed lower snake case, and event messages are fixed lowercase English phrases. Fields are static lower snake case keys; categories are closed `&'static str` values: new variant helpers use snake case with an underscore before every capital, while existing `Guard::name()` and `InvariantError::name()` remain verbatim. `operation_code: u16` comes from the architecture operation ID when applicable; otherwise `request_kind` is a static request variant name, never a Rust type path. `branch` and `driver` are static selectors. No generic `operation`, `standing`, `command`, `output_mode`, `exit_class`, or `result_published` field belongs in model events: `standing` describes observed test or target evidence, and the command fields belong to `cli-common`.

Every emitted cardinality is a noun plus `_count: u64`, with saturation at emission (`u64::try_from(n).unwrap_or(u64::MAX)`), so telemetry cannot fail an operation; a configured maximum is `step_limit: u64`, not a count. A future byte quantity would use a subject-first `_bytes: u64` name. A configured time bound may use `_ms`, but measured durations never become fields. `outcome` has only `completed`, `refused`, and `failed`; `refusal_kind` occurs only for `refused`, and `error_kind` only for `failed` or the exceptional invariant diagnostic. `phase` is a fixed step name only where a future event needs to identify a failed phase. No model field carries an amount, nonce, hash, transaction, signer, world, raw bytes, path, child output, free-form error text, or result payload (`[ADR010-rule:output:data-classification]`).

## Cost · `sec:tracing-model:cost`

Invariant checks, history scans, address-set construction, projections, and property traces can be long; enabled span close records expose their inclusive `busy_ns` and `idle_ns` without an `Instant` in model code. Entry fields use existing cheap lengths and static identifiers; completion counts use existing results or loop state. Do not recompute `maintenance_phase_potential`, duplicate an address census, clone a world, serialize a query, hash data, render an error, or read a result solely for telemetry. Span and event macros evaluate count conversions only when enabled; maintenance step counters advance with their loops because the operation already carries them, while property trace counters advance only when their event level is enabled. Any derived field requiring traversal is computed only after `tracing::enabled!` at its target and level. The domain potential still runs because it enforces validity, and `reserve_sat` is omitted from the genesis span.

## Testing · `sec:tracing-model:testing`

Model tests use a package-local capture subscriber with a workspace-inherited `tracing-subscriber` dev dependency and `tracing::subscriber::with_default`; it records typed event fields and span close records in memory without setting a global subscriber. A control transition and a subject one coordinate away assert the returned world or `Guard`, one DEBUG `completed` or `refused` completion, the static `refusal_kind`, and no WARN or ERROR on the expected refusal. An invariant-fault fixture asserts exactly one `model invariant failed` ERROR with `InvariantError::name()` plus the `execute` DEBUG `failed` completion, and the maintenance and property fixtures assert their terminal counts. Tests compare returned values with and without capture, assert span names, targets, levels, and parentage, and never assert elapsed thresholds or cross-thread event order.

Every test using scoped capture re-executes its exact full test path as the only selected test in a fresh child process marked by `TRIPOD_MODEL_CAPTURE_CHILD`; the parent requires a successful exit and exactly one passed test and includes child output in any failure. The child retains a process-wide capture-install mutex and rebuilds tracing's callsite interest cache inside `with_default` before the subject, so concurrently running uncaptured tests cannot alter its callsite interest.

No model test installs a process-global subscriber, writes a stream for its own progress, or captures process stdout to test a library without a writer. If a future model test spawns a thread that must carry tracing context, it clones the scoped dispatcher with `tracing::dispatcher::get_default(Dispatch::clone)` and enters it and the parent span on that thread. A future binary's subprocess tests, owned by that binary, check JSON stdout bytes, empty stdout before failure, `RUST_LOG=off` control records, panic and TTY behavior, and one enabled span close record. No shared test-helper crate is introduced.

## Implementation plan · `sec:tracing-model:implementation`

1. Add the package-local scoped capture helper, the test-only `tracing-subscriber` dev dependency, and static variant helpers for error enums that lack `name()`; register any new test source in `packages/model/meson.build`. This model-library commit is independent of `cli-common` and changes no stream contract.
2. Instrument `genesis`, `execute`, direct `check_invariant`, and `bind_execution` with the spans and one completion event per public call; route invariant detection through one `model::invariant` ERROR site before the `Guard::InvariantFailure` mapping. Add control, one-coordinate refusal, and invariant-fault tests; preserve every typed return and acceptance rule. This library commit is independent of binary subscriber setup.
3. Instrument the public conformance adapters and ledger comparison, with the private `observe_transition` and `index_history` phase spans but no duplicate completion events. Add accepted and typed-refusal fixtures; do not change realization evaluation or indexer validation. This library commit has no `cli-common` dependency.
4. Instrument maintenance and property drivers with one terminal summary each, reusing domain progress and count state; omit per-action driver events and test completed, zero-progress, and property-count paths. This library commit has no `cli-common` dependency.

ADR-010 and `cli-common` provide the early subscriber, control route, command span, terminal event, and span-close records required by an executable. The four model-library commits above are independent of executable startup; this package has no binary step. Any future executable that publishes model results installs the shared subscriber as its first action and tests its stdout and stderr contract in subprocesses.

## Open questions for the other packages · `sec:tracing-model:questions`

The cross-package choices affecting model are resolved: literal crate/module targets and unprefixed span names; exactly `completed`, `refused`, and `failed` outcomes; static `refusal_kind` for guards and `error_kind` for invariant failures; `operation_code: u16` where architecture defines one; `*_count: u64` observations; DEBUG expected refusals and repetitive transition spans; and one exceptional invariant ERROR owned at detection. Model reports no `standing` because it does not observe target acceptance, and only a command owns the final user-facing diagnostic. The shared subscriber owns process startup and span-close timing; the model library does not wait for it to implement its own spans and events.
