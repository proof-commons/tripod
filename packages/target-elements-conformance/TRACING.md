# Tracing engineering design: target-elements-conformance

## Purpose and shape · `sec:tracing-target-elements-conformance:purpose`

`target-elements-conformance` is the secretless harness that asks a caller-selected Elements executor about reviewed primitive fixtures, compound prototypes, and caller-planned operation steps. It supervises the process and line-delimited JSON exchange, binds handshake and environment observations, evaluates typed reports, and gates evidence; a handshake states provenance rather than authenticating the executor, and a mock run never satisfies the native gate.

The library exposes fixture and prototype censuses, constructor and commitment oracles, the protocol types, executor and progressive capture APIs, report evaluation and validation, gates, and conservation, normalization, and lifecycle document builders. The important public seams are `fixture::canonical_fixture_set`, `prototype::{constructor_case_matrix,wide_floor_case_matrix}`, `executor::{execute_canonical,execute_canonical_prototypes,execute_operations_captured,run_protocol}`, `validate::{evaluate,validate_native_report,gate}`, `prototype_validate::{evaluate_prototypes,validate_prototype_report,prototype_gate}`, and `emit::*_document`; `error::NativeConformanceError` carries typed refusals. `vectors` calls the executor and oracle APIs for native ceremonies and tests; `transaction` and `vectors` are test-only dependencies of this package, while `vectors` depends on this package for its own evidence path.

Seven binaries live in `src/bin/`: two checker commands, four `emit-*` document commands, and `mock-native-executor`, a test-subject program that deliberately produces malformed protocol frames. The first six publish reports or documents through `cli-common`; the mock publishes its documented protocol NDJSON directly. The library installs no subscriber. When vectors calls the library in one process, its `vectors::native_test` `execute_ceremony` span is the parent of this package's `executor_run` span; each process installs its own subscriber only at its executable entry point.

## Standard output and standard error · `sec:tracing-target-elements-conformance:streams`

Direct checker mode keeps one typed report JSON object plus newline on stdout; build mode writes the report and success stamp to argument-named assets and leaves stdout empty. The four `emit-*` commands keep one JSON object plus newline, with matrix `rows` and `requests` separate so expectations never enter executor requests. The mock's handshake, environment, case answers, and declared malformed fault frames remain its documented protocol stdout results. A runtime failure before publication leaves stdout empty; a short write can leave a partial record, and a result command refuses terminal stdout as ADR-010 requires (`[ADR010-rule:output:json]`, `[ADR010-rule:output:tty]`).

At protocol close, the first buffered byte after the final response is `TrailingProtocolData`, including a blank, unterminated, or oversized trailing record; no shutdown record-length limit reclassifies it. A violation already observable at that boundary keeps its refusal if the watchdog expires during cleanup, because scheduling must not replace observed protocol evidence with a later timeout. An EOF caused by watchdog expiry remains `ExecutorTimeout`, so silence never becomes a protocol refusal.

Every binary, including the mock, calls `cli_common::install_command_subscriber(command_name)` as its first statement. That shared call installs the one process-wide JSON subscriber and panic hook together; libraries and unit tests never do so. The subscriber's unfiltered `cli_common::control` route handles help, version, usage, TTY refusal, and panic with the existing ADR-010 control-record bytes, while its reloadable diagnostic route renders package events and span close records. Both routes share one locked stderr writer, so records do not interleave. Before parsing, the diagnostic filter uses nonempty `RUST_LOG` or `info`; after parsing, the runner reloads it using nonempty `RUST_LOG`, then `--debug`, then the command default. An invalid directive falls back to `info` and emits a WARN `filter directive rejected` event without echoing its value; required control records survive even `RUST_LOG=off`. A panic is at most one best-effort control record through a nonblocking lock, with payload hidden until parsed `--debug` enables it.

`cli-common` owns the INFO command span after parsing, around semantic work and publication, and its one terminal record: INFO `command completed` for success, ERROR `command failed` for operational failure, and a control record alone for usage or TTY refusal. Its custom-main API gives the mock the same span and terminal event; the mock passes the fixed safe kind word `protocol` or `io` to `command_failed` and never formats an I/O error into stderr. Command, output mode, exit class, and result-publication fields belong to that shared layer, not to this library. The mock's `NoisyStderr` event is WARN because the mock continues to produce its result; the parent's discarded arbitrary child stderr is never a first-party diagnostic. Every enabled span yields one subscriber close record with entry fields and `busy_ns: u64` and `idle_ns: u64`; there are no open or enter records, and nested durations are inclusive rather than separately additive.

ADR-010 requires the existing result shape, JSON control-record schema, TTY refusal, exit classes, panic disclosure rules, and safe-field policy, with every first-party stderr byte produced by the one subscriber (`[ADR010-rule:output:streams]`, `[ADR010-rule:output:data-classification]`). `execwrap` routes child bytes to explicit files, with no child-byte relay exception for either standard stream. The mock is a first-party test-subject program under the same stderr rule: its noise is a structured WARN event, while in-harness test cases remain outside the executable contract.

## Spans · `sec:tracing-target-elements-conformance:spans`

Targets below are explicit string literals rooted at the Rust library crate stem; names use lower snake case and contain no package prefix or dots. Entry fields are static categories or cheap existing numeric values; no span records an outcome or completed count. Outer `executor_run` is INFO because one run is bounded per command or ceremony, while repeatable library phases are DEBUG so their close records do not flood default stderr.

Public wrappers that call another public function in this crate use an uninstrumented internal core, so one external operation yields one completion event; cross-crate calls retain their own nested spans and events. A small codec or accessor gets no success span merely for symmetry. The parent vectors ceremony and child executor run share in-process span parentage only; no case ID, ceremony ID, span ID, raw request, or executable path is passed through the child protocol for correlation.

## Events · `sec:tracing-target-elements-conformance:events`

`outcome: &'static str` is exactly `completed` for a returned typed result, `refused` for an expected typed refusal, or `failed` for an operational fault. A completed report may contain failed cases, and a completed gate decision carries its separate `admitted: bool`; neither changes the operation outcome to `refused`. Every public operation's one completion event is inside its span, with the same tier on `completed` or `failed` and DEBUG on `refused`. A library failure returned to its caller does not emit ERROR: cli-common emits the single terminal command ERROR if the command fails. WARN is reserved for a recoverable anomaly after which a usable result still appears.

| Boundary | Target and level | Fixed message | Fields and conditional types |
|---|---|---|---|
| Supervised run returns a transcript | `target_elements_conformance::executor`, INFO | `executor run completed` | `outcome: &'static str` (`completed`), `workload: &'static str`, `case_count: u64`, `response_count: u64`, `attempt_count: u64` from attempts already made. |
| Supervised run returns an expected typed negative | `target_elements_conformance::executor`, DEBUG | `executor run completed` | `outcome: &'static str` (`refused`), `workload: &'static str`, `refusal_kind: &'static str` from the stable typed variant name (`malformed_response`, `trailing_protocol_data`, `protocol_record_too_large`, and peers), `phase: &'static str` (`startup`, `handshake`, `environment`, `execute`, `close`), `record_byte_limit: u64` only for a bound refusal; an unterminated oversized record has no known final size. |
| OS spawn fails after the existing bounded retry | `target_elements_conformance::executor`, DEBUG | `executor spawn failed` | `phase = "startup"`, `io_error_kind` (the standard-library error kind), `os_error: i32` when supplied by the OS. No path or child diagnostic bytes are recorded; the public startup refusal is unchanged. |
| Supervised run returns an operational failure | `target_elements_conformance::executor`, INFO | `executor run completed` | `outcome: &'static str` (`failed`), `workload: &'static str`, `error_kind: &'static str` from the stable typed variant name (`executor_startup_failed`, `executor_handshake_failed`, `executor_timeout`, and peers), `child_exit_code: i32` only when the child exited with a code. |
| Primitive or prototype matrix build completes or refuses | `target_elements_conformance::fixture` or `target_elements_conformance::prototype`, DEBUG | `matrix built` | `outcome: &'static str`, `matrix: &'static str`; on completion `row_count: u64`, `request_count: u64`, `search_attempt_count: u64` when already known; on refusal `refusal_kind: &'static str`. |
| Primitive or prototype report evaluation or validation returns | `target_elements_conformance::validate` or `target_elements_conformance::prototype_validate`, DEBUG | `report assessed` | `outcome: &'static str`, `report_kind: &'static str`; on completion `case_count: u64`, `passed_count: u64`, `failed_count: u64`; on refusal `refusal_kind: &'static str`; on fault `error_kind: &'static str`. |
| Native or prototype gate returns | `target_elements_conformance::validate` or `target_elements_conformance::prototype_validate`, DEBUG | `report gate completed` | `outcome: &'static str`, `report_kind: &'static str`; on completion `admitted: bool`, `mock: bool`; on typed refusal `refusal_kind: &'static str`; on fault `error_kind: &'static str`. |
| Matrix or report document build returns | `target_elements_conformance::emit`, DEBUG | `document built` | `outcome: &'static str`, `document_kind: &'static str`; on completion `row_count: u64` and `request_count: u64` where meaningful; on refusal `refusal_kind: &'static str`; on fault `error_kind: &'static str`. |
| Mock `NoisyStderr` behavior continues the exchange | `target_elements_conformance::mock_executor`, WARN | `mock executor diagnostic` | `behavior: &'static str` (`noisy_stderr`); no raw child text. |

The protocol setup and case phases emit no duplicate refusal event; their typed error reaches the enclosing run's one completion event. A spawn retry has no event per attempt; `attempt_count` summarizes it. A terminal spawn failure additionally records its OS cause before mapping to the public startup refusal. A watchdog expiry is `error_kind = "executor_timeout"`, not a second `timeout` flag. A forced kill after fully valid results may produce one WARN supervision anomaly, but timeout or incomplete results are `failed`, not WARN. `standing: &'static str` (`accepted`, `refused`, `unobserved`) and `observed_refusal_kind` are reserved for an event about a tested subject's observed evidence, such as a report case; neither describes this API's own refusal, and no per-case event is added by default.

## Naming · `sec:tracing-target-elements-conformance:naming`

Targets are explicit `target_elements_conformance::<domain>` literals for `executor`, `protocol`, `fixture`, `prototype`, `validate`, `prototype_validate`, `emit`, and `mock_executor`; binary-local events use the domain of their work, never a binary crate target or a `::command` suffix. The target owns the package name, so span names are lower snake case operations and fixed event messages are short lowercase English phrases. Field keys are lower snake case; a name derived from a variant has an underscore before every capital and then lowercase letters, while an existing stable variant `name()` or `as_str()` is reused verbatim. No `?Debug` or `%Display` of an input, error, or result enters a library event.

`refusal_kind` occurs exactly with `outcome = "refused"`, `error_kind` exactly with `outcome = "failed"`, and `phase` names a fixed operation step. Cardinalities are `<noun>_count: u64`, obtained with saturating conversion such as `u64::try_from(n).unwrap_or(u64::MAX)` so instrumentation cannot fail the operation; byte sizes are `<subject>_bytes: u64` and byte bounds `<subject>_byte_limit: u64`. `grace_ms` is a configured limit, not a measured duration. A child exit uses `child_exit_code: i32` only when a code exists. No generic `operation`, dynamic `case_id`, ceremony ID, domain amount, nonce, hash, transaction weight, raw bytes, witness, key, child argument, executable path, caller-supplied path, or free-form error becomes a field.

## Cost · `sec:tracing-target-elements-conformance:cost`

Only bounded public operations get INFO spans; repeatable phases are DEBUG, and no fast per-case or per-frame span or event is added. Entry fields use static categories and O(1) values already held. Completion counts come from the census, transcript, report, or search state already computed for the domain; optional derived counts are guarded by `tracing::enabled!`, and no collection is traversed, cloned, hashed, serialized, formatted, or timed merely to fill tracing fields. The supervisor's `Instant` remains necessary to enforce a correctness deadline, while subscriber close records supply measured busy and idle time; nested durations are inclusive and a collector computes exclusive time without an extra event field.

## Testing · `sec:tracing-target-elements-conformance:testing`

The executor-protocol integration harness additionally installs a narrow global test-writer subscriber for OS spawn-cause events, so ordinary failing tests retain the underlying kind and errno. It does not serialize exchanges; the existing missing-executable capture pins the cause fields. Library unit tests use a package-local capture subscriber from a workspace-inherited `tracing-subscriber` dev-dependency inside `tracing::subscriber::with_default`; they record event fields and span close records in memory, never install a global subscriber, and never assert exact durations or cross-thread order. Each capture test re-executes its own full `--exact` path as the sole selected test in a fresh child process marked by an environment variable; the parent requires successful exit and exactly one passed test and prints the captured child output on failure. Inside that child, each test binary serializes scoped subscriber installation with one static mutex and rebuilds the callsite interest cache inside `with_default` before invoking the subject; a regression test touches a span without capture and then requires one close record from each of two captured threads. Any spawned thread that must retain context explicitly captures the dispatcher with `tracing::dispatcher::get_default(Dispatch::clone)` and enters `with_default` and the parent span in that thread. A well-formed mock protocol exchange is the `completed` control; a single malformed frame is the one-coordinate-away subject, refused at the framing boundary with a DEBUG completion and no library WARN or ERROR. Report schema damage, mock gate evidence, and malformed document records supply typed negative subjects with controls and unchanged result bytes; infallible matrix and document builders have completed controls only because their signatures accept no subject that can be refused.

Subprocess tests, not unit tests, check the global bootstrap and stream bytes: direct report/document mode yields one parseable JSON result line; build mode writes explicit report/stamp assets and empty stdout; pre-publication failure leaves stdout empty; help, usage, TTY refusal, and panic still produce their control record under `RUST_LOG=off`; an enabled INFO span produces one close record with numeric `busy_ns` and `idle_ns`; and the mock's noise is a JSON WARN event. A separate local test child writes arbitrary stderr bytes so the parent discard rule is tested independently of the first-party mock. Tests themselves write no standard stream; diagnostic values become assertions and any required archived run report is an explicit file. No shared test-helper crate is introduced.

Vocabulary tests cover every literal name returned by the native-error and matrix-defect tracing tables against the snake_case grammar and its variant spelling, with a single-letter-word conversion pinned separately. Protocol-close tests distinguish an oversized trailing record from a watchdog-caused EOF without depending on scheduling.

## Implementation plan · `sec:tracing-target-elements-conformance:plan`

The commit sequence below records the implemented dependency order.

1. Library commit: added `executor_run`, `protocol_setup`, `protocol_cases`, and `executor_cleanup` spans and the single aggregate executor completion event, using typed `refusal_kind`/`error_kind`, `attempt_count`, and `child_exit_code`; tested a well-formed mock control and one malformed-frame refusal with a scoped subscriber. This work used the existing tracing dependency and added the test-only subscriber dependency.
2. Library commit: added fixture and prototype matrix, report evaluation, report validation, gate, and document spans and their one-per-operation completion events with existing count values; tested negative reports and mock-gate refusal without changing typed outputs. Vectors' parent `execute_ceremony` span can enclose this package's `executor_run` in the same process.
3. Binary commit: after ADR-010 and the shared subscriber were in place, switched the six report and document mains to `install_command_subscriber` as their first statement, kept their shared runners, and extended subprocess tests for help, usage and panic under `RUST_LOG=off`, stdout result bytes, build mode, exit classes and span close records. The runner reloads its process-global diagnostic filter after parsing; no package-local subscriber is installed.
4. Mock and test commit: switched `mock-native-executor` to the shared bootstrap, custom-main command span, and terminal event; replaced direct `NoisyStderr` text with the static WARN event; added a local arbitrary-stderr child fixture; and asserted protocol stdout bytes and the parent's child-stderr discard in subprocess tests. No production validator or protocol result changed.

Legacy panic-hook and tracing-init delegates remain in `cli-common` while other binaries migrate and are removed there after that migration; this package has no separate cleanup commit. The workspace's direct-stderr lint rule is outside this package.

## Open questions for the other packages · `sec:tracing-target-elements-conformance:questions`

The early-control question is settled: `cli-common` installs one subscriber and panic hook before parsing, keeps an unfiltered control route and a reloadable diagnostic route in one locked writer, and retains the ADR-010 control bytes. All seven binaries use that implementation; library instrumentation remains independently usable without a process-global subscriber.

The vocabulary question is settled: `completed`/`refused`/`failed`, `refusal_kind`/`error_kind`, saturating `u64` `_count` fields, static literal module targets, and DEBUG routine refusals are shared; `standing` and `observed_refusal_kind` describe target evidence rather than the library operation. Vectors' ceremony parents this executor's run in process, with no raw case identity or correlation token in protocol fields.

The testing and mock questions are settled: package-local scoped subscribers cover library events and close records, process-global controls are checked by subprocesses, and the first-party mock's stderr is JSON tracing. Arbitrary raw child bytes are supplied only by a local test child and discarded by the parent; the mock's declared malformed stdout frames remain protocol test results.
