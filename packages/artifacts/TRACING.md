# Tracing design for `tripod-artifacts`

## Purpose and shape · `sec:tracing-artifacts:purpose`

`tripod-artifacts` derives four generated publications from typed architecture, model and label sources. Its library renders the expected bytes in memory and compares them with an explicitly named generated directory; `generate-all` publishes the batch, while `check-generated` returns a freshness report without repairing files.

`src/lib.rs` owns the artifact census, validated rendering, `ArtifactFreshness` and the versioned `CheckReport`; `src/weld.rs` extracts the realization document's masthead and attached TOML for integrity tests. The two binaries assemble an argument-scoped `labels::RepositoryCensus` and use `cli-common` runners. Meson's `generated-check` target consumes the checker report and success stamp; `architecture`, `model` and `labels` provide typed inputs. Generated files are publications, not semantic inputs to other packages.

The library remains a pure caller-facing API except for the checker's directory reads. Tracing observes validation, rendering, comparison and structural extraction without changing returned bytes, reports, errors or publication order.

There is no package-source `print!`, `eprint!`, direct `stdout()` or `stderr()` call, custom telemetry counter, progress meter or elapsed-time recorder. Help, version, usage, TTY-refusal and panic JSON records now pass through `cli-common`'s unfiltered subscriber control route, including when `RUST_LOG=off`.

## Standard output and standard error · `sec:tracing-artifacts:streams`

`check-generated` retains the ADR-010 single-result contract: direct success writes exactly one newline-terminated `CheckReport` JSON object with `schema`, `generated_dir`, census-ordered `artifacts` (`name`, `status`), sorted `unexpected` and `current`; build mode writes the same object to `--report` and then touches `--stamp`, leaving stdout empty. A non-current report is a completed library result, but the binary exits 1, emits per-item defects and publishes neither stdout result nor success stamp. `generate-all` writes only the four assets beneath `--output` and leaves stdout empty. A stdout write failure may leave a partial record, as ADR-010 permits (`[ADR010-rule:output:streams]`, `[ADR010-rule:output:json]`, `[ADR010-rule:output:assets]`).

Each binary's first statement is `cli_common::install_command_subscriber(COMMAND_NAME)`, which installs the single JSON tracing subscriber and panic hook before clap parsing. The library installs neither. The subscriber's unfiltered control route renders help, version, usage, TTY refusal and panic in the existing control-record schema even with `RUST_LOG=off`; its filtered diagnostic route renders runtime events and enabled span-close records. Both routes share one non-interleaving locked stderr writer. Before parsing, diagnostics use nonempty `RUST_LOG` or INFO; after parsing the runner reloads nonempty `RUST_LOG`, then `--debug`, then the command's INFO default. An invalid filter falls back to INFO and produces a WARN record without echoing the directive. The shared panic route emits at most one best-effort record with a nonblocking writer, omitting payload until parsed `--debug` enables it (`[ADR010-rule:output:control-plane]`, `[ADR010-rule:output:early-startup]`, `[ADR010-rule:output:panics]`).

Under amended ADR-010, all first-party stderr bytes come from that subscriber, including early control records. `cli-common` owns the INFO `command` span around each runner's semantic closure and result publication, plus its one INFO `command completed` or ERROR `command failed` terminal event; a failure records `phase` (`execute`, `serialize` or `publish`) and centrally redacted `error` text. Usage and TTY refusal end with their control record alone. The checker owns only its located defect events, and the generator owns one recoverable unowned-file warning; neither binary adds a second command-wide span, terminal event or standard-error writer. The shared `publish_batch` span and event replace generator publication progress. No report, source text, raw argv, asset bytes, argument-derived path or free-form library error text becomes a tracing field (`[ADR010-rule:output:diagnostics]`, `[ADR010-rule:output:data-classification]`).

## Spans · `sec:tracing-artifacts:spans`

Targets are explicit string literals so filtering is stable across module moves and binary crate names. Every enabled span emits one JSON close record with its name, target, level, entry fields, `busy_ns: u64` and `idle_ns: u64`; there are no open or enter records. Nested durations are inclusive, and a collector derives exclusive time from parentage instead of summing parent and child as separate work.

| Operation | Span name | Target | Level | Entry fields (types) | Duration measured |
|---|---|---|---|---|---|
| Public `expected_artifacts` | `expected_artifacts` | `artifacts::render` | INFO | `artifact_count: u64` from the fixed census | Validates the typed draft and publication envelope, renders both architecture encodings, checks their round trips and derives label and model publications; nested architecture and labels work stays visible. |
| Public `check` | `check` | `artifacts::check` | INFO | `artifact_count: u64` from the fixed census | Covers expected-byte derivation, per-file reads and the unexpected-file scan; a negative freshness verdict is still a completed check. |
| Private render core called by `check` | `render_expected` | `artifacts::check` | DEBUG | `artifact_count: u64` | Separates derivation from directory I/O without calling the instrumented public `expected_artifacts` and emitting a second artifacts completion event. |
| Public `weld::masthead` and `weld::extract_appendix_toml` | `extract_weld` | `artifacts::weld` | DEBUG | `part: &'static str` (`masthead` or `appendix`) | Measures structural extraction without recording document text; the two entry points share one span name and differ by the static part field. |

There is no package-local `generate`, `check_command` or `publish_batch` wrapper span. `cli_common::command` includes the binary closure and result publication; `cli_common::publication` owns the INFO `publish_batch` span and a DEBUG `stage_asset` span per changed asset, with a static artifact role. A separate checker result-publication span is unnecessary because the shared command span covers it.

## Events · `sec:tracing-artifacts:events`

Every public artifacts operation that has a span emits exactly one completion event before returning. `completed` means it returned its typed result, even if `current` is false; `refused` means an expected validation or structural refusal; `failed` means an operational or internal failure. A refusal event is DEBUG, a completed or failed event takes its operation's INFO or DEBUG tier, and the command boundary alone emits the terminal ERROR for a returned failure. A private render phase has no separate completion event. The returned report and error remain authoritative.

| Boundary | Target | Level | Fixed message | Fields (types) |
|---|---|---|---|---|
| Public expected-byte derivation returns | `artifacts::render` | INFO on `completed` or `failed`; DEBUG on `refused` | `expected artifacts derived`, `expected artifact derivation refused`, or `expected artifact derivation failed`, selected by outcome | `outcome: &'static str`; `artifact_count: u64` on completion; `rendered_bytes: u64` on completion only when enabled; `refusal_kind: &'static str` exactly on refusal; `error_kind: &'static str` and optional `phase: &'static str` exactly on failure. |
| Public freshness check returns | `artifacts::check` | INFO on `completed` or `failed`; DEBUG on `refused` | `generated artifacts checked`, `generated artifact check refused`, or `generated artifact check failed`, selected by outcome | `outcome: &'static str`; `artifact_count: u64`, `stale_count: u64`, `missing_count: u64`, `unexpected_count: u64`, `current: bool` on completion; `refusal_kind: &'static str` exactly on refusal; `error_kind: &'static str` and optional `phase: &'static str` exactly on failure. |
| Public weld extraction returns | `artifacts::weld` | DEBUG | `document weld extracted`, `document weld extraction refused`, or `document weld extraction failed`, selected by outcome | `outcome: &'static str`, `part: &'static str`; `refusal_kind: &'static str` exactly on structural refusal or `error_kind: &'static str` exactly on operational failure. |
| Owned artifact is stale or missing and `check-generated` fails | `artifacts::check` | ERROR | `generated artifact not current` | `diagnostic_code: &'static str` (`stale` or `missing`), `artifact: &str` borrowed from the returned report and bounded to the four census names, `detail: &'static str` with the fixed generation-and-commit remediation. |
| Unowned file is present and `check-generated` fails | `artifacts::check` | ERROR | `unexpected file in generated directory` | `diagnostic_code: &'static str` (`unexpected`), `path: &str` relative to the checked directory, `detail: &'static str` with a fixed removal-or-census remediation. |
| Generator scan finds unowned files after publication | `artifacts::render` | WARN | `unowned files left in output directory` | `unowned_file_count: u64`. |

The typed refusal kind is a stable payload-free variant name from the first returned validation defect when several are returned; weld's structural branches use fixed local refusal kinds. Operational error kinds are fixed classes such as `io` or `serialization`, never formatted `anyhow` text. Located checker defects are the sole events here with a path or explanation; file-level defects have no source line or column to invent. The shared runner emits the single redacted terminal `command failed` event when the binary exits 1. `cli-common` alone emits the batch completion counts, while `architecture`, `labels` and `model` may emit their own nested library events for their public calls; artifacts does not repeat their details.

## Naming · `sec:tracing-artifacts:naming`

Use only the explicit targets `artifacts::render`, `artifacts::check` and `artifacts::weld`; binary-local checker defects use `artifacts::check`, and there is no `artifacts::command` target. Span names are unprefixed lower_snake_case operations, event messages are fixed short lowercase English phrases, and fields have static lower_snake_case keys. `outcome` is exactly `completed`, `refused` or `failed`; `current: bool` is the separate report verdict. `refusal_kind` names expected typed rejection, `error_kind` names operational failure, `phase` names a fixed step, and `diagnostic_code` names a located checker defect. The manifest and label refusal tables use the stable spellings of `ManifestError::name()` and `LabelErrorCode::as_str()`; every emitted table name matches lower snake case with an underscore at each capital boundary. `part` is `masthead` or `appendix`, `artifact` is one of the four static census names, and no path appears outside a failing checker's located unexpected-file defect.

Cardinalities end in `_count` and byte lengths in `_bytes`, both `u64`; converting an in-memory length uses saturation (`u64::try_from(n).unwrap_or(u64::MAX)`) so instrumentation cannot fail the operation. There are no bare `count`, `_len`, `byte_count`, measured-duration, generic `operation`, command-envelope or correlation-ID fields in this package. The shared subscriber supplies command identity through its parent span; `cli-common` alone owns `command`, `output_mode` (`stdout`, `asset`, `none`), `exit_class` (`success`, `failure`, `usage`) and `result_published`.

## Cost · `sec:tracing-artifacts:cost`

Validation, rendering, comparison and directory reads are domain work and run with or without a subscriber. Span entry fields use the fixed census length and a static weld selector; completion counts scan the returned report only inside an enabled INFO event. Compute the sum for `rendered_bytes` only inside an enabled INFO event and saturate it. Classify typed rendering refusals from the first existing architecture or label diagnostic only when an outcome event is enabled; weld's structural branches select fixed local kinds. Do not join defect strings, serialize a report, scan a collection, clone artifact bytes, format an argument path or start an `Instant` solely for disabled instrumentation. No argument-derived path is formatted for an event: the checker borrows only a name already found during its required directory scan and makes it relative to the checked directory. The generator's bounded warning uses a count instead of per-file formatting.

## Testing · `sec:tracing-artifacts:testing`

Library tests use a package-local capture subscriber with `tracing::subscriber::with_default`, recording events and span-close fields in memory without a global subscriber. Every capture test first re-executes its exact full test name as the only selected test in a fresh child process, with an environment marker to prevent recursion; the parent requires a successful child and a one-test-passed summary and includes the child's output in any failure. Inside that child, a process-wide install lock surrounds each capture, and the helper rebuilds tracing callsite interest inside `with_default` before running the subject; a regression first touches one callsite without capture, then captures it from two test threads and requires exactly one span close in each. A temporary generated directory supplies a current control and subjects one coordinate away for stale, missing and unexpected files; tests assert one `check` completion event, `outcome = "completed"`, the exact counts and `current` verdict, and unchanged `CheckReport` values and bytes with and without capture. A rendering refusal and a weld structural refusal assert DEBUG with `refusal_kind` and no WARN or ERROR library record. Tests assert target, level, name, message and fields, never duration magnitude or ordering across threads. A thread that must inherit a parent's capture explicitly carries that dispatcher and enters the parent span there; the two-thread regression installs a separate scoped subscriber inside each child.

Subprocess tests run the real binaries with separate captured streams: direct checker success is exactly one JSON result line, build mode writes byte-identical report and then a stamp, failing checks leave stdout empty and do not touch a success stamp, and generator stdout is empty. They parse every stderr line as either a control record or a tracing diagnostic/close record, assert the two located defect shapes and one generator warning, and check help, usage, TTY refusal and panic under `RUST_LOG=off`, including one enabled INFO span close record with numeric `busy_ns` and `idle_ns`. The test-only `eprintln!` was removed; test observations use assertions. A privileged process that can write into a read-only directory makes the failed-write test panic with an explanation unless `TRIPOD_ALLOW_PRIVILEGED_SKIP` is set; with that opt-in, the test instead asserts successful publication and no staged-file residue, so an unexercised negative path never silently passes. These process-global bootstrap and stream claims are never tested by installing a global subscriber inside a unit test.

## Implementation plan · `sec:tracing-artifacts:plan`

1. The library commit extracted an uninstrumented render core from `expected_artifacts`, made `check` call it inside `render_expected`, added the three public operation spans and their one completion event each, and added scoped control/refusal tests; the library installs no subscriber and preserves every public return value and byte.
2. The shared prerequisite amended ADR-010 and supplied the pre-parse `install_command_subscriber`, always-on control route, reloadable filter, command span and terminal records, span-close timing, and shared `publish_batch` instrumentation; `cli-common` retains compatibility delegates for binaries still using its older startup APIs.
3. The binary-startup commit switched both `main` functions to `install_command_subscriber(COMMAND_NAME)` as their first statement, retained INFO as their post-parse default, and added subprocess assertions for help, usage, TTY refusal, panic, `RUST_LOG=off`, stdout/report/stamp bytes and span-close shape.
4. The binary-event commit migrated `check-generated` to located defect events, removed generator per-artifact publication events, added its one counted unowned-file WARN, and asserted those fields in subprocess tests; `cli-common::command` and `cli_common::publication` remain the only command and batch publication spans.
5. Shared startup delegates and the workspace direct-stderr lint belong to the command layer; neither changes the artifacts API or results. The library commit removed this package's test-only `eprintln!`.

## Open questions for the other packages · `sec:tracing-artifacts:questions`

The shared choices are settled for this package: explicit crate-stem module targets and unprefixed span names; `*_count: u64` with saturating conversion; `outcome = "completed"` with a separate `current` verdict even for a stale report; one shared `publish_batch` span and event with no artifacts wrapper; and subscriber-produced span-close timing with no local stopwatch. Amended ADR-010 assigns the pre-parse subscriber and command outcome to `cli-common`; artifacts owns only its library observations and the checker's located defects.
