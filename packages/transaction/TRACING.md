# Transaction tracing engineering design

## Purpose and shape · `sec:tracing-transaction:purpose-shape`

`tripod-transaction` derives candidate ABIs, constructs target transaction bytes, validates offered views, and carries LIVE transfer and STATE maturity announcement candidates through finalization and authorization. Its typed refusals describe construction or decoding boundaries, not a target node's acceptance (`packages/transaction/src/error.rs`). This library has no binary.

`src/lib.rs` reexports compact ASH (`abi`, `request`, `construct`, `taproot`, `bytes`), LIVE (`live_abi`, `live_request`, `live_construct`, `live_materialize`, `live_finalize`, `live_handoff`, `live_signing`), and STATE (`state_abi`, `state_view`, `state_construct`, `state_confidential`, `state_finalize`, `state_signing`) paths. `operator_right`, `operator_membership`, `operator_signing`, `script_path_signing`, and `sponsor` supply authorization boundaries; `src/tests` holds unit and conformance subjects. Public results are typed ABIs, candidates, reports, bytes, and refusal enums; `vectors` and `target-elements-conformance` consume them.

Each instrumented public operation emits exactly one completion event inside its span on return. A same-crate public wrapper calls a private core to avoid duplicate completion records; cross-crate calls retain their own events. Small frequent value helpers have no success telemetry, though a useful refusal may have one DEBUG event. The `vectors` fixture or ceremony span parents transaction construction and signing; invoked lower-level work remains nested, including realization evaluation within a STATE ABI caller span. Transaction adds no correlation ID.

## Standard output and standard error · `sec:tracing-transaction:streams`

This library writes neither stream. ABI, report, encoded bytes, and refusal remain return values; requested reports and assets remain file results. A command publishing them serializes an explicit structured stdout result, normally one JSON object and newline or declared NDJSON, and leaves stdout empty on failure before publication. ADR-010 requires every first-party program stderr byte to come from its one `tracing` subscriber, which `cli-common` provides for binary callers (`[ADR010-rule:output:streams]`, `[ADR026-dec:tracing:core]`).

Transaction never installs a subscriber or panic hook. A binary caller installs `cli_common::install_command_subscriber(command_name)` as its first statement before parsing, then enters the shared INFO command span around work and publication; no parse span is required. `cli-common` owns the locked stderr writer with unfiltered control and filtered diagnostic routes, reloads its filter after parsing with precedence `RUST_LOG`, `--debug`, default, and emits an invalid `RUST_LOG` warning as a static subscriber event. Early help, usage, TTY, and panic controls pass through the unfiltered route and keep their control JSON bytes. Diagnostics use a shared JSON envelope with span context, and each enabled span gets one close record with `busy_ns` and `idle_ns`. The command emits one terminal INFO completion or ERROR failure; a returned library refusal is an input to that outcome. The panic hook emits at most one nonblocking record and exits 1; transaction does not use legacy setup delegates.

ADR-010 requires execwrap child output to route to explicit files and an unrouted request to fail before spawn. Transaction has no child stream route. Harness-free first-party programs follow the command contract; mock test subjects' own stderr comes from a subscriber, while harnessed test cases remain outside that contract (`[ADR010-rule:output:streams]`).

| Operator right `issue`, `replace`, `consume`, `retry`, `dispatch`, or `timeout` return | `transaction::operator_right` | DEBUG | `operator right issued`, `operator right replaced`, `operator right consumed`, `operator right retried`, `operator right dispatched`, or `operator right timed out` respectively | `outcome: &'static str`; `refusal_kind: &'static str` only on refusal. |

The `outcome` values are exactly `completed`, `refused`, and `failed`; these boundaries normally complete or refuse. A returned operational failure uses its span tier and `error_kind: &'static str`, never routine library ERROR; the command owner emits terminal ERROR. `refusal_kind` uses an existing stable variant `name()` where available or a static mapping, never rendered error text. When multiple defects arise, report the deterministic first refusal and an existing `defect_count: u64` if held. A negative domain verdict returned successfully has `outcome = "completed"` and a separate static verdict, not WARN or ERROR. No per-output completion event is emitted: `materialize_output` supplies its timing. No event asserts target acceptance, and `standing` belongs to evidence-producing vectors or conformance operations.

## Naming · `sec:tracing-transaction:naming`

Targets are explicit static literals `transaction::<owning_module>`; span names are short snake-case phrases without crate prefix or dot, and event messages are fixed lowercase English phrases. Field keys are static snake case; variant-derived `refusal_kind` values put an underscore before every capital and lowercase it, including single-letter words, while an existing stable `name()` or `as_str()` value is used verbatim. `family` is `compact`, `live`, `state` or `keyed`; a distinct inner phase, if needed, is `phase`, never `stage`. Upstream architecture codes use `operation_code: u16`, never a generic `operation` field. Transaction has no `standing`, `command`, `output_mode`, `exit_class`, or `result_published` field.

Counts use a specific `<noun>_count: u64` field with saturating conversion at emission (`u64::try_from(n).unwrap_or(u64::MAX)`); byte lengths use `<subject>_bytes: u64` such as `input_bytes`, and configured bounds use `<noun>_limit: u64` such as `attempt_limit`. Slow-unit progress, if justified later, uses `completed_count` and `total_count`; no bare plural, generic count, `_len`, or measured-duration field is used. Amount, nonce, hash, token, right checkpoint, transaction weight or virtual size, report contents, script, witness, key, argument-derived path, executable, child output, and rendered error are excluded from span and event fields even if held in a result.

## Cost · `sec:tracing-transaction:cost`

Proof generation, transaction serialization, hash derivation, refusal formatting, role maps, and census sets are real work. A span records only existing cheap values such as known slice length or static role, with numeric conversion at emission; optional derived detail is guarded by `tracing::enabled!` for its exact target and level. No instrumentation-only allocation, clone, formatting, hash, or timer is introduced. The parity-search counter remains in the supplied fixture for correctness; on an exhaustion refusal only, an enabled DEBUG event may read that outcome again to report `attempt_count`, with no iteration event. Disabled instrumentation leaves returned values and encoded bytes unchanged. Archival timing sidecars, where callers produce them, are explicit file results rather than tracing fields.

## Testing · `sec:tracing-transaction:testing`

The keyed arithmetic capability, leaf hash, NUMS digest, keyed control builder and crate-private borrowed equality receipt core are untraced. `keyed_public_boundaries_emit_once_and_capture_runs_exactly_one_test` uses the package capture mutex and exactly-one-child runner; it asserts one DEBUG span and close record, target/name/level/family, one terminal event, exact per-boundary literal message, outcome, refusal classification (absent on success), and success-only path counts. All six messages have distinct callsites. `keyed_refusal_trace_kinds_are_snake_case` checks both `TraceRefusal` tables. Production fixes `KeyedCurve`; the private test seam admits refusal outcomes only. No local duration or secret is recorded.

Package-local capture subscribers under `tracing::subscriber::with_default`, with `tracing-subscriber` as a dev dependency, assert span name, target, level, typed fields, close record, and exactly one completion event per public operation. Every scoped capture test re-executes its own full test path as the sole selected test in a fresh child process, marked by a package-specific environment variable; the parent requires a successful exit and a summary showing exactly one passed test, and includes the child's stdout and stderr in any failure. Inside that child, one process-wide mutex covers the capture and the callsite interest cache is rebuilt inside `with_default` before invoking the subject, because concurrent uncaptured tests can otherwise change process-wide callsite interest while a scoped subscriber is installed. A regression calls an instrumented boundary once without capture, then captures it separately on two test threads and requires exactly one span per capture. Tests cover completed controls and one-coordinate refused subjects at every reachable fallible declared boundary; the infallible STATE finalizer has a completed control and no refusal path to test. STATE ABI derivation has a completed control only: its defensive refusals require a nonprototype linked status, a different reviewed revision, or a different fixed obligation census, none of which can be produced through the package's validated-view and reviewed-target constructors. A refusal stays DEBUG with `refusal_kind` and creates no WARN or ERROR. Tests compare returned values and encoded bytes with and without capture. The helper stays local, not in a shared crate or process-global subscriber; a subject that spawns threads propagates the scoped dispatcher explicitly.

The two `Instant` values and stdout writes in `state_abi_validation_tests.rs` are removed while call-count assertions remain. There are no replacement test spans or events: the harness supplies per-test duration and the counts are correctness oracles. Library tests neither capture process streams nor exercise global bootstrap. Binary packages and `cli-common` use subprocess tests for early bootstrap, unfiltered control and filtered diagnostic records, one structured stdout result or empty stdout on pre-publication failure, and panic handling. An ignored hand-run test needing progress may install a scoped JSON stderr subscriber; ordinary tests stay stream-silent.

## Implementation plan · `sec:tracing-transaction:implementation-plan`

1. Instrument public ABI derivation and construction with explicit targets, outer spans, one fixed-message completion event, static refusal mapping, and package-local scoped collector tests. This library step is independent of the shared command subscriber.
2. Instrument confidential materialization with outer and inner spans, one boundary event, and parity-exhaustion `refusal_kind` plus existing `attempt_count`; verify proof and transaction values stay out of fields. This depends on commit 1's vocabulary and collector, not on `cli-common`.
3. Instrument finalization, authorization, decoding, and operator-right boundaries with the same outcome and level rules, preserving upstream parent spans and downstream child spans. This depends on commit 1's event convention and is independent of the shared command subscriber.
4. Remove the two test timers and stdout reports while retaining count assertions; add one-coordinate refusal and no-subscriber equivalence coverage, propagating the dispatcher if a test threads. This depends on commit 1's scoped collector and needs no command subscriber.

`cli-common` provides the ADR-010 subscriber and command runners used by binary owners. Transaction has no binary bootstrap or subprocess stream test. `vectors` and conformance callers consume the instrumented library under their fixture or ceremony parents and own their binary output setup. The workspace owns the direct-stderr lint configuration.

## Open questions for the other packages · `sec:tracing-transaction:open-questions`

- Cross-package targets use crate stem and owning module, while `cli-common` owns the command target. Transaction uses `family` for compact, live, state, and keyed; shared outcomes are `completed`, `refused`, and `failed`, with typed library refusal at DEBUG.
- A caller may observe a returned refusal, but each public operation records its own one completion event; a same-crate wrapper calls a private core, and a command emits its terminal command record. Neither nested library refusal is WARN nor returned operational failure is library ERROR.
- Subscriber span close supplies timing; test sweep wall and call counts stay with the harness and assertions. No transaction value or arbitrary error text enters tracing fields, and no report summary is promoted to an event merely for collection.
- `cli-common` owns filter precedence, early control, panic, and JSON schema. Transaction uses no command subscriber because it is a library; binary callers use the shared bootstrap.

Request parent decoding uses the existing untraced decoder core; parent and commitment checks are untraced. The link and member binder retain their own owner events. `keyed_request_boundaries_trace_one_completion_or_refusal` isolates exactly one child and checks each request boundary’s own terminal event on success and refusal.

The keyed sponsor verifier exposes DEBUG spans `keyed_sponsor_digest` and `verify_keyed_sponsor` with `family: &'static str = "keyed"`. Each emits exactly one own event: `keyed sponsor digest completed` / `keyed sponsor digest refused`, or `keyed sponsor verification completed` / `keyed sponsor verification refused`. Events carry `outcome: &'static str`; refusals also carry `refusal_kind: &'static str`. Both wrap untraced cores and record no keys, amounts, signatures or timers.

`keyed_construction_boundaries_trace_exactly_one_own_terminal_event` and `keyed_sponsor_boundaries_trace_exactly_one_own_terminal_event` use the exactly-one-child capture helper on accepted and refused calls. Admission invokes untraced construction and verification cores; the reused tapscript weight boundary retains its own owner span/event. No measured duration or secret enters these events.

`keyed_construction_refusal_tables_are_snake_case` covers both common `TraceRefusal` implementations. Completion and refusal events include `family = "keyed"`. `KeyedPolicy::new` is an untraced configuration-value constructor; only construction, admission and the diagnostic verifier entries publish transaction-boundary events.
