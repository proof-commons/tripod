# Tracing design for `tripod-realization`

## Purpose and shape · `sec:tracing-realization:purpose`

`realization` is a target-independent library between the finite `architecture` registry and consumers in `compiler`, `model`, `tapscript`, `linker`, `transaction`, `vectors`, and `target-elements-conformance`. It has no binary, command-line parser, file output, or process-stream writer (`src/lib.rs:7`, `Cargo.toml:11`). Its typed results and refusals remain the authority for semantic decisions; tracing observes work and never changes an accepted or refused boundary.

`derive` binds and validates an architecture and explicit scope, derives compact-ASH, live-transfer, and maturity-announcement declarations, builds expression, relation, constructibility, lifecycle, and disclosure graphs, analyzes declassification, and validates the assembled spec (`src/derive.rs:268`, `src/derive.rs:296`). `ScopedRealizationSpec` exposes stable typed projections and evaluates an `OperationObservation` into a `ConformanceReport` with separate semantic-conformance and external-evidence decisions (`src/derive.rs:184`, `src/evaluate.rs:222`).

The public modules also own scope and binding checks, observation normalization, STATE metadata transition and canonical codec, typed values and identifiers, and explicit refusal types (`src/observation.rs:278`, `src/state.rs:315`, `src/state_codec.rs:256`, `src/error.rs:45`). `compiler` revalidates the spec and evaluates offered observations (`packages/compiler/src/input.rs:179`, `packages/compiler/src/sponsor_region.rs:89`), `model` normalizes observations (`packages/model/src/conformance.rs:313`), `transaction` evaluates a STATE ABI observation (`packages/transaction/src/state_abi.rs:321`), and `vectors` derives and evaluates realization fixtures (`packages/vectors/src/maturity_continuity.rs:847`).

## Standard output and standard error · `sec:tracing-realization:streams`

This library publishes nothing to standard output. `ScopedRealizationProjection`, `ConformanceReport`, canonical STATE bytes, and refusal values remain typed returns. An executable that publishes a result uses one JSON object and newline or documented NDJSON through `cli-common`; assets go to explicit paths. A failure before publication leaves stdout empty, and a result command refuses terminal stdout, as ADR-010 requires (`[ADR010-rule:output:streams]`), (`[ADR010-rule:output:json]`), (`[ADR010-rule:output:assets]`), and (`[ADR010-rule:output:tty]`).

The package has no direct stderr writer; its diagnostics are structured `tracing` events with fixed fields. The library never installs a subscriber or panic hook. A first-party executable installs the one shared `cli-common` JSON subscriber and panic hook before parsing, then its runner applies the `RUST_LOG`, parsed `--debug`, command-default filter precedence; an always-enabled control route preserves help, version, usage, TTY-refusal, and panic records even when `RUST_LOG=off`. The control and filtered diagnostic routes share a locked writer, so stderr remains non-interleaving JSON; the panic route is best effort and nonblocking. The shared subscriber emits one close record per enabled span with `busy_ns: u64` and `idle_ns: u64`, on by default for INFO spans. Realization does not write or time those records itself.

The executable's first statement calls `cli_common::install_command_subscriber(command_name)`. Before parsing, its diagnostic filter is nonempty `RUST_LOG` or `info`; after parsing, a runner reloads the filter through a process-global handle, and an invalid directive falls back to `info` with one WARN `filter directive rejected` event that omits the directive. The always-on control route classifies help, version, and status as INFO, usage and TTY refusal as WARN, and panic as ERROR without changing their ADR-010 JSON wire schema. The diagnostic route retains its JSON `timestamp`, `level`, `target`, `fields`, and span context. The shared INFO `cli_common::command` span surrounds execution and publication, and its terminal event reports one success or failure; realization copies none of those command fields. The shared panic hook emits at most one record through a nonblocking path and exits 1.

ADR-010 requires every first-party stderr byte to be subscriber-produced, and `cli-common` installs that subscriber before parsing; early control records use its unfiltered route. `execwrap` routes raw child bytes only to explicit files, while realization's typed-return contract remains unchanged (`[ADR010-rule:output:streams]`). No realization event carries raw observation bytes, owner IDs, witnesses, amounts, architecture hashes, provenance, caller-supplied paths, or free-form error text (`[ADR010-rule:output:data-classification]`).

## Spans · `sec:tracing-realization:spans`

Targets are explicit literal Rust crate/module paths. Spans hold only cheap entry context; completed counts, refusals, and outcomes belong in events. The subscriber records inclusive duration at close, and a collector derives exclusive time from parentage rather than adding a child duration to its parent.

| Span name | Literal target | Level | Entry fields (type) | Duration reason |
|---|---|---|---|---|
| `derive` | `realization::derive` | INFO | `scope_operation_count: u64` | Covers architecture binding, declaration derivation, graph assembly, and final validation for one request. |
| `assemble` | `realization::derive` | DEBUG | `operation_count: u64` | Separates graph construction and declassification from initial architecture binding. |
| `validate_spec` | `realization::validate` | DEBUG | `operation_count: u64`, `relation_count: u64` | Measures bidirectional architecture and constructibility checks, including direct `validate_against` calls. |
| `normalize_observation` | `realization::observation` | DEBUG | `operation_code: u16`, `object_count: u64`, `region_count: u64` | Measures sorting and reference, region, root, and flow checks; callers may repeat it for many observations. |
| `evaluate_operation` | `realization::evaluate` | DEBUG | `operation_code: u16`, `relation_count: u64`, `expression_count: u64`, `operator_membership_supplied: bool` | Covers expression and relation evaluation per observation; DEBUG prevents many INFO close records in a conformance run. |
| `project_spec` | `realization::derive` | DEBUG | `operation_count: u64`, `relation_count: u64` | Measures cloning and stable graph projection for compiler and comparison consumers. |

`operation_code` is the numeric result of `architecture::OperationId::code()`, never an operation name string, Rust type path, or graph index. There is no per-relation span, and the small STATE decoder and maturity transition have no span or success event. A caller such as `compiler::input`, `model::conformance`, or `transaction::state_abi` provides parent context; realization does not duplicate command fields.

## Events · `sec:tracing-realization:events`

`outcome: &'static str` has exactly `completed`, `refused`, and `failed`: a completed report can have a negative verdict, a refusal is an expected typed `Err`, and a failure is an operational or internal `Err`. `ArchitectureHashUnavailable` is operational; `UnknownRelation` and `UnknownEvaluatedExpression` are internal invariant failures when reached by a validated spec. Every instrumented public operation with a span emits one completion event inside it; its public method and free-function aliases call an uninstrumented internal core so a same-crate call does not duplicate the event. A call into another crate may legitimately emit that crate's own event. Expected refusals are DEBUG regardless of the span tier; a returned failure takes the span tier, never WARN or ERROR. Only a command boundary emits the final ERROR diagnostic for a returned failure. WARN is reserved for a recoverable anomaly after which a result remains usable; realization currently has no such event.

| Public boundary and event message | Literal target | Level by outcome | Fields (name: type) |
|---|---|---|---|
| `derive` — `realization derived` | `realization::derive` | INFO `completed`; DEBUG `refused`; INFO `failed` | Always `outcome: &'static str`; on completion `operation_count: u64`, `expression_count: u64`, `relation_count: u64`, `constructibility_node_count: u64`, `lifecycle_node_count: u64`, `disclosure_node_count: u64`; on refusal `refusal_kind: &'static str`, `phase: &'static str`, and `defect_count: u64` when architecture validation returns several defects; on failure `error_kind: &'static str`, `phase: &'static str`. |
| Direct `ScopedRealizationSpec::validate_against` — `realization validated` | `realization::validate` | DEBUG for all outcomes | Always `outcome: &'static str`; on completion `operation_count: u64`, `relation_count: u64`; on refusal `refusal_kind: &'static str`; on failure `error_kind: &'static str`; `phase: &'static str` only when the failing step is not clear from the span. |
| Direct `validate_observation` or `OperationObservation::validate_and_normalize` — `observation normalized` | `realization::observation` | DEBUG for all outcomes | Always `outcome: &'static str`, `operation_code: u16`; on completion `object_count: u64`, `region_count: u64`; on refusal `refusal_kind: &'static str`; on failure `error_kind: &'static str`. |
| Either public evaluation method — `operation evaluated` | `realization::evaluate` | DEBUG for all outcomes | Always `outcome: &'static str`, `operation_code: u16`; on completion `conformant: bool`, `evidence_complete: bool`, `passed_count: u64`, `statically_validated_count: u64`, `evidence_required_count: u64`, `failed_count: u64`, `blocked_count: u64`; on refusal `refusal_kind: &'static str`; on failure `error_kind: &'static str`. |
| `project` or `project_scoped_realization` — `realization projected` | `realization::derive` | DEBUG for all outcomes | `outcome: &'static str` (`completed`), `operation_count: u64`, `relation_count: u64`. |
| `decode_state_metadata` refusal — `state metadata refused` | `realization::state_codec` | DEBUG | `outcome: &'static str` (`refused`), `refusal_kind: &'static str`, `input_bytes: u64`. |
| `announce_maturity` refusal — `maturity transition refused` | `realization::state` | DEBUG | `outcome: &'static str` (`refused`), `refusal_kind: &'static str`. |

For evaluation, `outcome = "completed"` says only that a report was returned. `conformant` and `evidence_complete` are separate returned decisions; `RelationStatus::EvidenceRequired` is not counted as a failure, and `Failed` and `Blocked` remain distinct. No realization event uses `standing`, which is reserved for observed test-subject evidence in callers. An `evaluate_operation` call uses the normalization core and emits only its own completion event, while a direct normalization call emits its own; `derive` likewise uses internal validation without causing a second realization validation event.

## Naming · `sec:tracing-realization:naming`

Targets use explicit literal `realization::<module>` strings. Span names are lower snake case without a package prefix or dot; event messages are fixed lowercase English phrases; field keys are lower snake case. The closed `outcome` vocabulary is `completed`, `refused`, `failed`; the derivation `phase` vocabulary is `binding`, `scope`, `declaration`, `assembly`, `validation`; other phase labels, if needed, name the fixed step that ended and never repeat the span name. `refusal_kind` is the payload-free snake-case variant identifier of the closed `RealizationError` enum in `src/error.rs`, selected by an exhaustive static mapping that inserts an underscore before every capital; for `ArchitectureValidationFailed` it uses the first returned `ManifestError::name()` verbatim and adds `defect_count`, since that variant wraps an ordered defect collection. Codec and maturity events use the existing stable kebab-case `StateMetadataRefusal::name()` and `MaturityTransitionRefusal::name()` values verbatim. `error_kind` is the fixed operational class or snake-case variant name, such as `architecture_hash_unavailable` or `internal_invariant`; an error's `Display` or `Debug` text is never a field.

The only operation identity is `operation_code: u16`; there is no generic `operation`, command, output-mode, or schema field in this library. Cardinalities use descriptive `<noun>_count: u64` and byte amounts use `<subject>_bytes: u64`; a `usize` length converts with saturation at emission (`u64::try_from(n).unwrap_or(u64::MAX)`) so instrumentation cannot fail the operation. No measured duration, nonce, amount, right, hash, caller-supplied path, raw bytes, report body, or free-form provenance becomes a field. Counts are per-operation observations, never a mutable telemetry store (`[ADR026-dec:tracing:core]`).

## Cost · `sec:tracing-realization:cost`

Span entry fields use input lengths, graph lengths, and `OperationId::code()` values the operation already holds. The six derivation counts read constructed graph sizes; no projection is built merely to log them. The five report-verdict counts require one pass over an already returned report and are computed only under `tracing::enabled!` at the event's literal target and DEBUG level. An exhaustive static error-kind match reads the variant without formatting its payload. There is no per-relation event, extra clock, graph traversal, cloned observation, encoded metadata copy, or error string made solely for tracing. With no subscriber, disabled callsites do not perform optional work, and the domain checks still run (`[ADR026-dec:tracing:core]`).

## Testing · `sec:tracing-realization:testing`

Package tests use a local `tracing-subscriber` dev dependency and wrap one call in `tracing::subscriber::with_default` with an in-memory capture of event fields and span-creation records. Every capture test re-executes itself as the only selected test in a fresh child process through `std::env::current_exe()`, `--exact` and its full test path, and a child-marker environment variable; the parent requires a successful exit and exactly one passed test and includes child output on failure. The capture helper holds a process-wide install mutex for the whole capture and rebuilds the callsite interest cache inside `with_default` before the subject runs; a regression first touches a callsite without capture, then captures it from two threads and requires one span in each. Assert literal targets, levels, names, fixed messages, typed fields, and one completion event per public boundary; never install a global subscriber or assert a duration value. If implementation later spawns a thread, propagate its dispatcher explicitly and enter the parent span there, because a scoped dispatcher is thread-local. A small package-local helper is sufficient; no shared test-helper crate is added.

Use an accepted control and a one-coordinate-away negative observation that still returns a `ConformanceReport`: both evaluation events are DEBUG with `outcome = "completed"`, one has `conformant = true` and the other `conformant = false`, and neither produces WARN or ERROR. Assert that both emitted report booleans equal the returned report's methods. Separate malformed-observation, STATE codec, and maturity-transition subjects assert DEBUG `refused` with the stable `refusal_kind`; a derivation refusal asserts its fixed `phase`. Check every literal realization error kind against the lower snake-case grammar and the architecture error kind against `ManifestError::name()`. Compare returned reports, refusals, and encoded bytes with and without the scoped capture to prove instrumentation does not change semantics. Test code itself writes no standard stream.

This pure library has no process-stream test. Executable owners test the shared subscriber bootstrap, early controls with `RUST_LOG=off`, panic, JSON stderr span-close records, and the documented JSON stdout or explicit-asset contract in subprocesses using `cli-common`. Those tests do not depend on a process-global subscriber inside realization's unit tests.

## Implementation plan · `sec:tracing-realization:plan`

1. Add the exhaustive static `RealizationError` classification and count-conversion helper, then instrument `derive`, internal assembly, and direct `validate_against` with the named spans and one completion event per public call. One library commit; it changes no typed return and has no `cli-common` dependency.
2. Instrument public observation normalization, both evaluation entry points, and projection through private cores with DEBUG spans and one completion event each; guard the five verdict counts with `tracing::enabled!` and add control versus one-coordinate-negative scoped subscriber tests. One library commit; it depends on the names and helpers in commit 1.
3. Add only DEBUG refusal events to `decode_state_metadata` and `announce_maturity`, using their existing stable `name()` values, and add scoped refusal tests that compare unchanged return values with and without capture. One library commit; it depends on the local test capture from commit 2.

The shared `cli-common` subscriber and amended ADR-010 are in force. Executable owners migrate their entry points and test the JSON stdout/stderr contract around realization calls; realization has no binary step. Shared compatibility delegates remain until executable migrations are complete, and the workspace ban on direct nonshared `stderr()` use belongs to the orchestrator. The library commits above do not depend on a subscriber installation in realization.

## Open questions for the other packages · `sec:tracing-realization:questions`

- Target filtering is resolved to explicit crate-stem/module literals such as `realization::evaluate`; no package-wide alias or binary role suffix is needed.
- Architecture operation identity is the numeric `operation_code: u16`; `outcome` has only `completed`, `refused`, and `failed`, while `conformant` and `evidence_complete` carry the report verdict.
- An expected typed refusal is DEBUG; a returned operational failure stays at its span's tier, and the executable's shared command boundary owns the final ERROR diagnostic. Realization emits no duplicate nested warning.
- Tests use a package-local scoped capture rather than a shared helper or global subscriber; process-stream and early-control assertions belong to executable subprocess tests using the shared bootstrap.

## Keyed boundary probe · `sec:tracing-realization:keyed-probe`

The experimental keyed declaration and validation spans are DEBUG and carry operation counts. Validation emits a completed/refused outcome and a payload-free refusal kind; span-close records supply timing. No key contents, history contents or native evidence is emitted. Existing attestation entry instrumentation remains unchanged.
