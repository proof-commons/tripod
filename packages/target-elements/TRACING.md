# Tracing engineering design for `target-elements`

## Purpose and shape · `sec:tracing-target-elements:purpose`

`tripod-target-elements` is a library of typed, reviewed Elements tapscript target facts: primitive and encoding contracts, authorization and confidential-value facts, resource bounds, capability dependencies, transaction-form rules, and immutable evidence requirements. It states the target behavior the project reviewed; it does not execute a script, observe a node, or produce target-native evidence.

`src/lib.rs` exports the public types and operations; `definition.rs` assembles and validates a `TargetDefinition`, `weld.rs` checks agreement among its views, and `deployment.rs` validates development bindings. The other modules supply individual contracts and registries, while `src/tests/` and `tests/public_api.rs` exercise the public boundary. There is no binary or `main` in this package.

`tapscript`, `linker`, `transaction`, `vectors`, and `target-elements-conformance` consume its reviewed wrapper or projections. A validated definition proves internal coherence; promotion to `ReviewedElementsTapscriptDefinition` additionally requires typed equality with the first-party declaration. A development binding can fail on environment, identifiers, version, activation, capability status, or resource overrides. `TargetError` and ordered `Vec<TargetError>` values are returned to callers, not printed here. A completed validation event never claims that a node accepted a program or that evidence was discharged.

## Standard output and standard error · `sec:tracing-target-elements:streams`

This library publishes no standard-output result. Its structured results remain typed return values: validated wrappers, projections, and ordered defect collections. An executable that presents them owns serialization: stdout carries one JSON object and newline, documented NDJSON, or nothing, while assets use explicit paths. ADR-010 requires `execwrap` to write child bytes only to explicit file routes and refuse an unrouted stream with a usage record and exit 2 before spawning; its child-status relay remains. This library has no relay or asset writer of its own (`[ADR010-rule:output:streams]`, `[ADR010-rule:output:json]`, `[ADR010-rule:output:assets]`).

This library has no direct standard-error output. Its observations are `tracing` events; the library installs no subscriber or panic hook and never writes stderr directly. A binary caller decides whether a returned refusal fails its command, then emits one terminal command diagnostic through `cli-common`. This package's DEBUG refusal event is not a second user-facing error. Events omit raw inputs, identifiers, paths, executable arguments, error text, results, scripts, bytes, witnesses, keys, and child output; entry context is limited to safe version and count scalars (`[ADR010-rule:output:data-classification]`).

ADR-010 requires each first-party executable to call `cli_common::install_command_subscriber(command_name)` first, installing one JSON subscriber and the panic hook before parsing. Its always-enabled control route and filtered diagnostic route share a locked stderr writer, preserve the control-record schema, keep early argv and payload omission, and route even `RUST_LOG=off` control records through the subscriber; no first-party stderr byte uses a direct early writer. The diagnostic route starts with nonempty `RUST_LOG` or INFO, then its process-global reload handle applies nonempty `RUST_LOG`, parsed `--debug`, or the command default after parsing; an invalid directive falls back to INFO with a fixed warning that omits the directive. A panic record uses a nonblocking lock and may be dropped on contention or re-entry before exit 1. Compatibility startup delegates remain a shared CLI concern; none is installed by this library (`[ADR010-rule:output:streams]`, `[ADR010-rule:output:early-startup]`, `[ADR010-rule:output:diagnostics]`, `[ADR010-rule:output:panics]`, `[ADR010-rule:output:implementation]`).

The shared diagnostic route retains JSON records with timestamp, level, target, fields, and span context. It emits one close record per enabled span, with name, target, level, entry fields, `busy_ns: u64`, and `idle_ns: u64`; no open or enter records are needed. The shared INFO `cli_common::command` span begins after parsing with `command: &'static str` and `output_mode: &'static str` and encloses command work and publication, including an instrumented async future. Its terminal INFO `command completed` event carries `exit_class = success`, `output_mode`, and `result_published: bool`; its ERROR `command failed` event carries `exit_class = failure`, a fixed `phase`, and centrally redacted `error` text from the supplied `Display` value. Usage and TTY refusal use their unfiltered control record alone. Package library spans nest under that command span when a binary calls them.

| Check a deployment declaration, `validate_development_binding` at `src/deployment.rs:294` | `validate_development_binding` | `target_elements::deployment` | DEBUG | `contract_version: u32`, `required_capability_count: u64`, `override_count: u64` | Walks capabilities and overrides; duration isolates binding work. |
| Weld a reviewed definition to a development binding, `validate_reviewed_development_binding` at `src/deployment.rs:439` | `validate_reviewed_development_binding` | `target_elements::deployment` | DEBUG | `contract_version: u32` | Includes validation and a full target projection clone. |

These are the five public work boundaries selected for timing; small accessors, constant constructors, and `bind_development_target` do not warrant a span. Spans carry entry context only. `reviewed_definition` includes its validation work, `promote_reviewed_definition` includes expected-declaration construction, and `validate_reviewed_development_binding` includes validation and projection. A subscriber's nested durations are inclusive; a collector derives exclusive time from parentage and never sums those inclusive values as independent wall. The shared subscriber emits close records by default for enabled spans; DEBUG keeps these repeated static checks out of the default INFO stream (`[ADR026-dec:tracing:core]`).

## Events · `sec:tracing-target-elements:events`

| Public return boundary | Explicit target | Level | Fixed message | Fields (types) |
|---|---|---|---|---|
| `reviewed_elements_tapscript` | `target_elements::definition` | DEBUG | `reviewed definition built` | `outcome: &'static str`; `defect_count: u64`; `refusal_kind: &'static str` only on refusal. |
| `validate_target_definition` | `target_elements::definition` | DEBUG | `target definition checked` | `outcome: &'static str`; `defect_count: u64`; `refusal_kind: &'static str` only on refusal. |
| `validate_as_reviewed_elements` | `target_elements::definition` | DEBUG | `reviewed definition promotion checked` | `outcome: &'static str`; `refusal_kind: &'static str` only on refusal. |
| `validate_development_binding` | `target_elements::deployment` | DEBUG | `development binding checked` | `outcome: &'static str`; `refusal_kind: &'static str` only on refusal. |
| `validate_reviewed_development_binding` | `target_elements::deployment` | DEBUG | `reviewed development binding checked` | `outcome: &'static str`; `refusal_kind: &'static str` only on refusal. |

Each external call emits exactly one completion event inside its span when it returns. `outcome` is `completed` for a returned wrapper and `refused` for a returned typed error; these operations currently have no operational failure branch. A future operational failure uses `outcome = failed` and `error_kind: &'static str`, never a `refusal_kind`. A refusal event is DEBUG regardless of any enclosing tier, while a returned operational failure event takes its span's tier; only the command boundary emits the terminal ERROR. No kind field appears on a completed event. A validator returning `Vec<TargetError>` emits its length as `defect_count`, zero on completion, and the first error's variant as `refusal_kind` on refusal; the existing stable defect order makes that choice deterministic.

`reviewed_elements_tapscript`, `validate_as_reviewed_elements`, and `validate_reviewed_development_binding` call uninstrumented internal validation or declaration cores, rather than calling an instrumented public wrapper. Thus the outer public call has one event, not a second event for the nested work. A caller that separately invokes `validate_target_definition` receives that operation's own event. There is no per-opcode, per-defect, per-capability, or progress event, and a completed static declaration is never reported as target-native evidence.

## Naming · `sec:tracing-target-elements:naming`

Every target is an explicit literal Rust crate stem plus owning module: `target_elements::definition` or `target_elements::deployment`. Span names are unprefixed lower snake case operations; event messages are fixed lowercase English phrases, with machine meaning in static lower_snake_case fields. `contract_version: u32` is the safe entry context. `opcode_count`, `encoding_count`, `capability_count`, `evidence_count`, `required_capability_count`, `override_count`, and `defect_count` are `u64` observations; convert a local `usize` at emission with `u64::try_from(n).unwrap_or(u64::MAX)` so instrumentation cannot panic or truncate. This package emits no byte, duration, limit, progress, command, `family`, `operation_code`, `standing`, or domain-verdict field. A future operational fault may add a fixed `phase` such as `validate`, but no generic `operation` or `stage` field duplicates the span name.

The closed `outcome` vocabulary is `completed`, `refused`, `failed`. `refusal_kind` is present exactly on `refused` and names the first returned `TargetError` variant without its payload in snake_case, with an underscore before every capital after the first; `error_kind` is reserved for `failed` and has no current value here. The fixed `refusal_kind` vocabulary from `src/error.rs` is listed below so adding an error variant requires an explicit instrumentation review rather than a debug-formatted fallback.

## Cost · `sec:tracing-target-elements:cost`

Span fields read a copied version and existing map or set lengths; they never clone maps, build a projection, format an error, or walk a registry for telemetry. `refusal_kind` comes from a static variant match only on a returned error; its payload remains in the returned value. The one event per external call and DEBUG tier avoid item-proportional output. Any future derived field must be computed only inside `tracing::enabled!` for its target and level or through lazy formatting. Without a subscriber, the instrumentation does not allocate, hash, traverse, sample a clock, or maintain a separate counter; span timing is subscriber work (`[ADR026-dec:tracing:core]`).

## Testing · `sec:tracing-target-elements:testing`

Use a package-local capture subscriber built on the workspace-inherited `tracing-subscriber` dev dependency, installed only around each test call with `tracing::subscriber::with_default`. It records typed event fields and span-close metadata in memory; tests assert target, level, name, fixed message, count and kind values, never elapsed magnitudes or order across threads. No test installs a global subscriber; the two-thread regression installs one scoped subscriber per thread under the package-local lock.

Each scoped capture test re-executes its exact full test path as the sole selected test in a fresh child process, marked by a package-specific environment variable; the parent requires a successful child exit and a summary showing exactly one passed test, and includes the child's output in any failure. The child keeps the package-local install lock and rebuilds the process-wide callsite interest cache inside `with_default` before the subject runs, so unrelated parallel tests cannot change its capture interest. The two-thread cache regression runs inside that isolated child.

Test a valid reviewed declaration against a one-defect mutated definition, and a valid development binding against a one-coordinate refused binding. Each external call must yield one completion event, with `completed` or DEBUG `refused`, the expected first `refusal_kind`, the saturating `u64` defect count where applicable, and no WARN or ERROR from this library. Test a reviewed wrapper call that internally validates yet emits only its outer event. Assert the returned values, stable error order and multiplicity, and projections are identical with and without capture; instrumentation must not change an acceptance boundary.

An exhaustive test reads the same static name table as `TargetError::refusal_kind`, checks every value against the lowercase snake_case grammar, rejects duplicate names, and pins representative names including `opcode_id_mismatch`; the match over `TargetError` remains exhaustive so a new variant must join this table.

This library has no binary and no process stream writer. Executable owners test actual stdout bytes, JSON-only subscriber-produced stderr, control records under `RUST_LOG=off`, span-close records, panic behavior, and exit classes in fresh subprocesses. A command that publishes a single result owes one JSON object and newline or empty stdout before publication failure; a local-dispatch unit test cannot prove that global process contract (`[ADR010-rule:output:json]`, `[ADR010-rule:output:control-plane]`).

## Implementation plan · `sec:tracing-target-elements:plan`

1. Commit `feat(target-elements): trace target definition validation`: split the definition validator and reviewed-declaration construction into uninstrumented cores with instrumented public wrappers; add the `validate_definition` and `reviewed_definition` spans, one completion event per external call, static first-defect variant mapping, saturating count conversion, and scoped control/refusal tests; remove `use tracing as _;` in `src/lib.rs`. This library step uses the core `tracing` dependency and a test-only `tracing-subscriber` dependency; it has no shared subscriber prerequisite.
2. Commit `feat(target-elements): trace reviewed promotion and development binding`: instrument reviewed promotion and both development-binding boundaries through internal cores, add their completion events and scoped valid/one-coordinate-refused tests, and check that nested public calls emit only one event while returned errors and projections stay unchanged. This step depends on commit 1's vocabulary and core split, with no binary bootstrap prerequisite.
3. Executable owners, including `target-elements-conformance`, own subscriber bootstrap in each main and subprocess assertions for JSON stdout, subscriber-produced JSON stderr, early controls under `RUST_LOG=off`, and span-close records. This package has no binary step; its library instrumentation is complete. Shared startup compatibility and the workspace direct-stderr lint belong outside this package.

## Open questions for the other packages · `sec:tracing-target-elements:questions`

The cross-package choices are settled for this package: an operation result is `completed`, `refused`, or `failed` rather than a claim of target acceptance; expected typed refusals stay DEBUG and carry `refusal_kind`; targets are explicit module paths under `target_elements`; emitted counts are saturating `u64` fields; and enabled span-close records carry inclusive `busy_ns` and `idle_ns` for a collector to attribute without summing nested durations. `cli-common` owns the subscriber and ADR-010 stream implementation; this library owns neither subscriber setup nor native-evidence standing.
